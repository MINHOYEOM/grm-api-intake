## 7. 5단계로 넘어가는 조건 (전부 채워야 한다)

1. 3단계: 편집팀이 git handoff 로 2회 발행 성공.
2. 4단계: 백업 Routine 이 git handoff·git 반납으로 1회 이상 정상 동작(주중 리허설 가능).
3. 그림자 비교(R2): 2주 연속 "노션에만 있는 행 0"(설명된 것 제외), 칸 차이는 전부 설명됨.
4. 감시 그림자(R4·R5): 2주 연속 판정 차이 0 이거나 전부 "정본 쪽이 맞다"로 설명됨.
5. 노션 전용 행 0(§3 dry-run).
6. `intake_queue` 넣기 기준 전환(W1)과 중복 판정 전환(R1)을 **같은 PR 로** 낸다 — 따로 바꾸면 사이에 새 소식이 대기열에서 빠지거나 지난 소식이 다시 들어온다. 백필 수집기가 넣는 행에는 출처 표식을 남겨 대기열에 들어가지 않게 한다.
7. 노션 Intake DB 전체 내보내기 보관.

## 8. 확인하지 못한 것

- 백업 Routine 이 저장소 브랜치에 push 할 수 있는지(커넥터 권한) — 4단계의 전제.
- `GRM_SYSTEM.md` 안의 노션 서술. 단계가 넘어갈 때마다 해당 절을 고친다.
- `docs/` 아래 설계·결정 문서 다수는 노션을 언급하지만(건수만 셌다) 실행 경로가 아니다 — 은퇴 때 현재 사실로 고치거나 archive.
- 클라우드 Routine 의 실제 프롬프트가 저장소 파일과 같은지는 저장소 밖이라 여기서 확인할 수 없다(편집팀은 파일을 읽는 방식으로 11-13 확인됨, 백업 Routine 은 미확인).
