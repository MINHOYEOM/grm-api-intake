# B1 업체 정적 페이지 주간 갱신 조사

2026-11-25 기준 로컬 코드와 Git 이력을 조사했다. 로컬 `origin/main`과 같은 커밋(`8029c96d`)의 전용 작업 트리를 사용했다. 실제 네트워크 호출 금지에 따라 열린 PR, GitHub Actions 실행 기록, 라이브 배포 상태는 조회하지 않았다. 이번 운영 실패의 원인은 확인되지 않았다.

## 갱신 경로

1. `.github/workflows/grm-findings-docs.yml`이 토요일 18:25 UTC(일요일 03:25 KST)에 `findings_docs_refresh.py`를 실행한다. 공개 anon RPC에서 `web/data/findings_docs.json`을 만들고, 변경이 있으면 골든을 재생성해 후보 PR을 연다. 문서 수 축소가 기본 10% 이상이면 사람 검토로 남기고, 나머지는 CI 통과 후 자동 머지하는 설정이다.
2. `.github/workflows/grm-web-deploy.yml`은 `web/**` 변경 push 등을 받아 `web/render.py`로 정적 사이트를 만든다. 렌더러는 `findings_docs.json`을 업체 키로 묶어 문서가 두 건 이상이며 유효하고 고유한 슬러그가 있는 업체의 `/findings/firm/{slug}/`를 만든다. 영어판은 해당 업체의 영어 문서가 두 건 이상일 때 같은 슬러그를 쓴다.
3. `grm-fda-citation-firms-refresh.yml`은 업체·조항 페이지의 FDA 지적 조항 블록만 별도로 갱신하며 수동 실행 전용이다. 로컬 Git에서 문서 스냅샷의 마지막 변경은 2026-11-22 `ad0560aa`(#1863)이다. 이 기록으로 라이브 배포 완료 여부를 판단할 수는 없다.

## 코드로 확인한 결함과 수정

- `GRM_PUBLISH_TOKEN`과 `ADMIN_GITHUB_ACTIONS_TOKEN`이 모두 비어 있으면 `gh pr merge`는 `github.token`을 사용했다. 이 토큰으로 발생한 main push는 웹 배포 워크플로를 시작하지 않는다. 자동 머지 대상에서만 후보 PR 생성 뒤 토큰 유무를 확인한다. 전용 토큰이 없으면 오류를 표시하고 CI 호출과 자동 머지를 차단한다. 실제 시크릿 상태는 확인하지 않았다.
- 기존 `[findings-docs]` 이슈는 정본 조회 단계 실패에만 열렸고, 조회 성공 뒤 골든·PR·CI·머지가 실패해도 닫힐 수 있었다. 갱신 작업 어느 단계가 실패하든 같은 이슈를 열거나 갱신한다. 작업이 성공하고 변경이 없거나 머지 단계가 성공했을 때 이슈를 닫는다. 축소로 사람 검토 중인 후보는 복구로 처리하지 않는다. 이 경보는 주간 갱신 작업을 추적하며 라이브 도달 여부는 별도 배포 단계에서 확인해야 한다.
