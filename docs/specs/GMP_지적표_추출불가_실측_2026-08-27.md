# GMP실사 지적 표 추출 실패 — 전수 실측과 4개 접근 실패 기록 (2026-08-27)

`GRM_SYSTEM.md` §6.2 `GMP-TABLE-PAGEBREAK` 의 근거 문서. **등록 당시 전제가 세 군데 틀렸고**,
수리 시도 네 가지가 전부 실패했다. 다음 시도가 같은 막다른 길을 반복하지 않도록 남긴다.

## 3. 시도한 접근 네 가지 — 전부 실패

| 접근 | 결과 |
|---|---|
| `find_tables(strategy="text")` / `"lines_strict"` | 헤더가 **한 번도** 검출되지 않음. `text` 전략은 페이지를 글자 위치별로 잘게 쪼개 `['', '의약', '품', '제', '조소', ...]` 같은 셀을 낸다 |
| 줄 단위 텍스트 파싱 (분야 통제어휘로 행 분할) | 48/71 "회수"되지만 **내용이 뒤섞인다** — 텍스트 읽기 순서가 근거법령 칸과 지적사항 칸을 교차시켜, 지적 문장이 `legal_basis` 로 들어가고(`"[별표 1] 제5호 포함하여 문서관리 규정을 개정할 것"`) 꼬리말이 `summary` 로 샌다. **발행 불가 품질** |
| 좌표 기반 칸 재구성 (`get_text("words")` + 헤더 x 경계) | 헤더 행이 단어로 온전히 존재하지 않아(5개 중 4개만 검출) 칸 경계가 틀린다. `구분` 칸이 `[별표` 를 삼키는 식 |
| `find_tables` 허용오차 스윕 8종 (`snap_tolerance`·`join_tolerance`·`edge_min_length`·`intersection_tolerance`) | 표본 24건에 대해 **전 설정 0/24** |

★**격자선이 없어서가 아니다.** 벡터 line/rect 개수 중앙값이 CONTROL 1,215 · TARGET 1,169 로
사실상 같다. 선은 있는데 PyMuPDF 가 표로 엮지 못한다.

## 4. 텍스트층 자체가 깨진 문서가 섞여 있다

71건 중 **10건은 0 마스킹**(`00000000…` 이 본문 자리에), **9건은 세로 분해**
(`의 / 약 / 품 / 관 / 리 / 과`). 파서로 고칠 수 있는 대상이 아니다.

## 5. 판정 및 다음 시도에 남기는 것

**결정론 파서로는 닫히지 않는다.** 이 시스템의 지적 표 상세는 "생성 0 → 환각 0" 이 전제인데,
줄 파싱 산출물은 **근거법령 칸에 지적 문장이 들어가는** 수준이라 없는 것보다 나쁘다
(규정에 대한 거짓 진술이 된다).

현실적 경로는 둘뿐이다.
1. **OCR 기반 표 재구성** — 이 프로젝트가 GMP 트랙에서 의도적으로 피해 온 방향이다
   (`collect_mfds_gmp_inspection` 상단 주석: "새 의존성·OCR·LLM 없음").
   채택하려면 그 설계 결정을 먼저 뒤집어야 한다.
2. **원천에 구조화 데이터 요청** — 식약처가 지적사항을 표가 아닌 형태로 제공하면 해소된다.

발행 화면 기준 손실은 현재 **0 이다** — 지적 표 없는 발행 GMP실사 카드 21건 중 현재 파서로
회수되는 것은 0건이고, 회수 가능한 23건은 발행 창 밖이거나 이미 반영돼 있다. 즉 **급하지 않다.**

## 6. 같은 조사에서 나온 **반대 방향** 결함 — 가림막(redaction) (2026-08-27)

위 §1~§5 는 "왜 추출이 안 되나"를 판다. 그 과정에서 **반대 질문**의 답이 나왔다 —
**추출해도 되는 것인가.**

식약처는 일부 문서에서 지적(보완)사항 요약·근거법령 칸을 **검은 막대로 가려** 배포한다.
그런데 그 막대는 글자를 지운 게 아니라 **살아 있는 텍스트 위에 덧그린 벡터 사각형**이라
`page.get_text()` 는 막대 **아래 글자를 그대로 돌려준다**. 파서는 원천이 의도적으로 감춘
문장을 읽어 내고 있었다.

- 육안 확인: `gmpinspect-1P0r6voXjK9` p3 — 보이는 지적 줄과 검은 막대가 섞여 있는데,
  우리 산출에는 **가려진 줄의 문장이 들어 있다**.
- 실측(CONTROL 194문서/934행): 가려진 단어 보유 **17문서**, 그중 **14문서가 35행**을 낸다
  (조사 단계 기록은 13문서였다 — 세는 기준의 차이이고 아래 §"세는 기준이 결론을 바꾼다"
  에서 정확히 가른다. 행 수 35 는 일치한다).
- ★**발행 브리프 카드 도달 0건**(`web/data/briefs/*.json` 전건 대조). 실사고가 아니라
  **잠복**이다 — 그 문서가 발행되거나 소급되는 순간 그대로 실현된다.

### 탐지 기준 (실측으로 고정)

| 항목 | 기준 |
|---|---|
| 막대 | `fill` 채널 평균 **< 0.25** 인 drawing 의 `re` 항목 중 **가로 ≥ 20pt · 세로 ≥ 5pt** |
| 가려진 단어 | 단어 rect 면적의 **절반 넘게** 한 막대와 겹칠 때 |

★크기 하한이 판별의 전부다. §3 이 실측했듯 이 문서들의 벡터 도형은 페이지당 1,000개대라,
하한 없이 모으면 **표 괘선과 밑줄이 전부 막대**가 되어 멀쩡한 표가 통째로 사라진다.

★`fill` 이 회색조 단일 스칼라 `0.0` 으로 오는 경우가 있다 — falsy 라 `if not fill` 로
거르면 **진짜 검은 막대를 놓친다**(가드가 조용히 무력화되는 형태).

### 두 번째 형태 — 텍스트층 `0000…` 마스크

§4 가 센 "0 마스킹 10건"이 같은 가림의 다른 형태다. 이쪽은 지운 자리에 `0000…` 런이
들어가 `0000 0000 0000` 같은 행을 낸다. 좌표가 필요 없으므로 **PDF·HWPX 두 경로 공통**
으로 `_normalize_deficiency_table` 에서 함께 버린다.

### 판정 — 행을 통째로 버린다

지적 한 행은 「분야·근거법령·지적사항」이 묶여 **하나의 규제 진술**이 된다. 가려진 칸만
비우면 **남은 칸이 온전한 진술처럼 읽히는** 행이 카드에 실린다: 근거법령이 빈 행은 "근거
없이 지적받았다"로, 지적내용이 빈 행은 "근거법령만 있고 지적은 없다"로 읽힌다. 규정에
대한 거짓 진술이므로 **없는 것보다 나쁘다** — §5 가 줄 파싱 산출물을 기각한 것과 같은
기준이다. 버린 행은 기존 강등 경로(요약카드 유지)로 조용히 떨어진다.

### fail-closed 의 경계

같은 "판정 불능"이라도 두 자리의 답이 다르다.

| 상황 | 처리 | 이유 |
|---|---|---|
| 좌표를 행에 대응 못 시킴(행 수 불일치·병합 셀·완결성 미달) | **표 전체 폐기** | 어느 행이 오염됐는지 말할 수 없다 |
| `get_drawings()` 자체가 실패 | 가드 미적용(`[]`) | 여기서 fail-closed 로 가면 **가림막 없는 문서 전부**가 영향을 받아 "안 가려진 문서는 바이트 불변"이라는 대전제가 깨진다 |

### 검증 — CONTROL 194문서 전건 실측 (2026-08-27, run 33063283255)

`verify_gmp_redaction_guard.py` — **같은 PDF 바이트·같은 프로세스**에서 규칙만 켜고 꺼
산출 sha256 을 대조한다(커밋을 갈아끼우면 그 사이 다른 변경분이 섞인다). 판정 기준은
지문 일치 외에 **부분수열**: 가드는 행을 *버리는* 일만 해야 하고, 더하거나 고치면 안 된다.
러너 실행은 `.github/workflows/grm-gmp-redaction-verify.yml`(dispatch 전용) — nedrug 는
러너 IP 를 차단하므로 **`MFDS_HTTP_PROXY` 가 없으면 전건 실패**한다(0건 가드로 막는다).

| 항목 | 실측 |
|---|---|
| 열람 | **194/194**(프록시 경유·다운로드 실패 0) |
| baseline 이 DB 저장값(`gmp_deficiencies`)을 재현 | **194/194**, 총 **934행** — 즉 baseline = 지금 발행 계약이 보는 값 그대로 |
| **산출 지문 불변** | **180문서** |
| 가드 발동 | **14문서 · 35행 제외**(934 → 899) |
| **부분수열 위반** | **0** — 가드는 행을 고치지 않았다 |

### 세는 기준이 결론을 바꾼다 — 17 / 14 / 3

같은 사실을 세 가지로 셀 수 있고, 셋 다 적어 두지 않으면 다음 사람이 다시 센다.

- **가려진 단어를 *가진* 문서 = 17** (표 산출과 무관하게 전 페이지를 센 원문 사실)
- **가려진 단어가 지적 *행*에 걸린 문서 = 14** (가드가 실제로 행을 버린 문서)
- **가려진 단어는 있으나 산출이 그대로인 문서 = 3**
  (`1OyiGZ6FoW5`·`1P0r6voXjFi`·`1P0r6voXjL2` — 막대가 표지·머리말 등 지적 행 밖에 있다)

★**이 3문서가 가드의 정밀도를 증명한다** — 막대가 있다고 문서를 통째로 버리는 게 아니라
행 단위로 가른다. `1P2hKsqMr6T`(3→2)·`1P41wm3_bah`(5→2)는 **문서 안에서도** 갈랐다.
fail-closed(표 전체 폐기)가 넓게 발화하고 있었다면 이 5문서가 전부 0행이 됐을 것이다.

★조사 단계 기록은 "13문서/35행"이었다. **행 수 35 는 정확히 일치**하고 문서 수만 하나
다르다. 차이는 `1OyuoHKrL9G`·`1P2UhIKFRbG` 두 문서다 — 둘 다 가려진 단어가 **1개**뿐이고
baseline 산출이 `근거법령='' · 지적사항='-'`(각각 `'b'`) 인 **한 글자짜리 쓰레기 행**
하나다. "행을 낸다"에 이런 행을 넣느냐 빼느냐가 13 과 14 를 가른다. 어느 쪽으로 세든
**실질 내용의 손실은 없다**(버려지는 것이 원래 지적사항이 아니다).

### `0000` 규칙은 CONTROL 에서 **완전히 중복**이다

텍스트층 규칙이 먹은 9문서 23행은 **전부 벡터 막대 규칙에도 걸린다**(교집합 9문서).
즉 CONTROL 기준으로 이 규칙이 추가로 잡아내는 문서는 **0건**이다 — 당연하다. 원천은
막대를 그리면서 그 아래 글자를 `0000` 으로 채웠으므로 같은 자리가 두 번 걸린다.

★그래도 남긴다. 이 규칙의 값은 CONTROL 이 아니라 ①§4 의 TARGET 10건(막대 없이 텍스트만
`0000` 인 문서) ②**HWPX 경로**(좌표가 없어 막대 규칙 자체가 없다) 에 있다.

★`gmp_deficiency_table_status` 어휘는 손대지 않았다(raw_payload·health 카운터 바이트
불변). "원천이 감춤"과 "우리가 못 읽음"을 상태값으로 가르는 것은 별건이고, 지금은 WARN
로그로만 남긴다.

### 코퍼스 문서 id

CONTROL(194) 과 TARGET(97) 의 id 는 `document_id` 에서 `gmpinspect-` 접두를 뗀 값이며,
PDF 는 `https://nedrug.mfds.go.kr/cmn/edms/down/{id}` 로 재현 가능하다(2026-08-27 전건 200 OK).
목록은 아래 SQL 로 언제든 재생성된다 — 손목록을 여기 박아 두면 낡는다.

```sql
select case when coalesce(raw_json::json->>'gmp_deficiency_table_status','') = 'extracted'
            then 'CONTROL' else 'TARGET' end grp,
       count(*), string_agg(replace(document_id,'gmpinspect-',''), ',' order by document_id)
from raw_signals
where source_kind='gmp-inspection'
  and coalesce(raw_json::json->>'attachment_file_format','') = 'pdf'
  and (coalesce(raw_json::json->>'gmp_deficiency_table_status','') = 'extracted'
       or coalesce(raw_json::json->>'attachment_deficiency_assessment','') in ('present','unknown'))
group by 1;
```
