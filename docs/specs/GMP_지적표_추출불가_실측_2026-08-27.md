# GMP실사 지적 표 추출 실패 — 전수 실측과 4개 접근 실패 기록 (2026-08-27)

`GRM_SYSTEM.md` §6.2 `GMP-TABLE-PAGEBREAK` 의 근거 문서. **등록 당시 전제가 세 군데 틀렸고**,
수리 시도 네 가지가 전부 실패했다. 다음 시도가 같은 막다른 길을 반복하지 않도록 남긴다.

## 1. 등록 전제의 오류

| 등록된 내용 | 실측 |
|---|---|
| "페이지에 걸쳐 이어지면 `find_tables()` 가 인식 못 해 0행" | **페이지 걸침이 아니다.** Guangdong 은 p1 표가 아예 미검출 + p2 조각만 검출(헤더 없음), 서울대병원은 **양 페이지 모두 표 0개** |
| "두 문서"(`1Pz0eO3IuUQ`, `1PxzwRCkCdX`) | **71문서.** 텍스트층에 지적 표 헤더가 실재하는데 추출 0행인 문서 전수 |
| "별개로 보이던 두 결손이 같은 뿌리" | **뿌리가 다르다.** DB 상 Guangdong = `skipped-type`(추출 시도조차 안 함), 서울대병원 = `empty`(실행 후 0행) |

★Guangdong 의 `skipped-type` 은 **이미 해소됐다** — 2026-08-12 유형 게이트 기본값 반전으로
지금은 `periodic` 으로 판정된다. 남은 문제는 표 검출 자체다.

## 2. 회귀 코퍼스 (291 PDF)

`raw_signals` 의 `source_kind='gmp-inspection'` · `attachment_file_format='pdf'` 기준.

- **CONTROL 194건** — 현재 `gmp_deficiency_table_status='extracted'`. 총 **934행**.
  수리를 채택하려면 이 194건의 산출이 **바이트 불변**이어야 한다.
- **TARGET 97건** — 지적사항 `present`/`unknown` 인데 표가 안 잡힌 문서.
  - 23건은 **현재 파서로 이미 추출된다**(63행) — 옛 손목록 유형 게이트(`skipped-type`) 시절
    수집분이라 재실행이 없었을 뿐이다. 다만 2022~2023년 문서가 대부분이라 발행 창 밖이고,
    그중 발행분에 있는 3건은 **이미 상세를 싣고 있다**(typegate 백필로 반영됨).
  - 3건은 텍스트층에도 헤더가 없다(표 없음이 정상).
  - 1건은 `pre_market`(설계상 표 없음).
  - **71건이 진짜 결손** — 텍스트층에 표가 실재하는데 0행.

문서 id 목록은 이 문서 §5.

## 3. 시도한 접근 네 가지 — 전부 실패

| 접근 | 결과 |
|---|---|
| `find_tables(strategy="text")` / `"lines_strict"` | 헤더가 **한 번도** 검출되지 않음. `text` 전략은 페이지를 글자 위치별로 잘게 쪼개 `['', '의약', '품', '제', '조소', ...]` 같은 셀을 낸다 |
| 줄 단위 텍스트 파싱 (분야 통제어휘로 행 분할) | 48/71 "회수"되지만 **내용이 뒤섞인다** — 텍스트 읽기 순서가 근거법령 칸과 지적사항 칸을 교차시켜, 지적 문장이 `legal_basis` 로 들어가고(`"[별표 1] 제5호 포함하여 문서관리 규정을 개정할 것"`) 꼬리말이 `summary` 로 샌다. **발행 불가 품질** |
| 좌표 기반 칸 재구성 (`get_text("words")` + 헤더 x 경계) | 헤더 행이 단어로 온전히 존재하지 않아(5개 중 4개만 검출) 칸 경계가 틀린다. `구분` 칸이 `[별표` 를 삼키는 식 |
| `find_tables` 허용오차 스윕 8종 (`snap_tolerance`·`join_tolerance`·`edge_min_length`·`intersection_tolerance`) | 표본 24건에 대해 **전 설정 0/24** |

★**격자선이 없어서가 아니다.** 벡터 line/rect 개수 중앙값이 CONTROL 1,215 · TARGET 1,169 로
사실상 같다. 선은 있는데 PyMuPDF 가 표로 엮지 못한다.

## 4. 텍스트층 자체가 깨진 문서가 섞여 있다

71건 중 **10건은 0 마스킹**(`00000000…` 이 본문 자리에), **9건은 세로 분해**
(`의 / 약 / 품 / 관 / 리 / 과`). 파서로 고칠 수 있는 대상이 아니다.

## 5. 판정 및 다음 시도에 남기는 것

**결정론 파서로는 닫히지 않는다.** 이 시스템의 지적 표 상세는 "생성 0 → 환각 0" 이 전제인데,
줄 파싱 산출물은 **근거법령 칸에 지적 문장이 들어가는** 수준이라 없는 것보다 나쁘다
(규정에 대한 거짓 진술이 된다).

현실적 경로는 둘뿐이다.
1. **OCR 기반 표 재구성** — 이 프로젝트가 GMP 트랙에서 의도적으로 피해 온 방향이다
   (`collect_mfds_gmp_inspection` 상단 주석: "새 의존성·OCR·LLM 없음").
   채택하려면 그 설계 결정을 먼저 뒤집어야 한다.
2. **원천에 구조화 데이터 요청** — 식약처가 지적사항을 표가 아닌 형태로 제공하면 해소된다.

발행 화면 기준 손실은 현재 **0 이다** — 지적 표 없는 발행 GMP실사 카드 21건 중 현재 파서로
회수되는 것은 0건이고, 회수 가능한 23건은 발행 창 밖이거나 이미 반영돼 있다. 즉 **급하지 않다.**

### 코퍼스 문서 id

CONTROL(194) 과 TARGET(97) 의 id 는 `document_id` 에서 `gmpinspect-` 접두를 뗀 값이며,
PDF 는 `https://nedrug.mfds.go.kr/cmn/edms/down/{id}` 로 재현 가능하다(2026-08-27 전건 200 OK).
목록은 아래 SQL 로 언제든 재생성된다 — 손목록을 여기 박아 두면 낡는다.

```sql
select case when coalesce(raw_json::json->>'gmp_deficiency_table_status','') = 'extracted'
            then 'CONTROL' else 'TARGET' end grp,
       count(*), string_agg(replace(document_id,'gmpinspect-',''), ',' order by document_id)
from raw_signals
where source_kind='gmp-inspection'
  and coalesce(raw_json::json->>'attachment_file_format','') = 'pdf'
  and (coalesce(raw_json::json->>'gmp_deficiency_table_status','') = 'extracted'
       or coalesce(raw_json::json->>'attachment_deficiency_assessment','') in ('present','unknown'))
group by 1;
```
