# 방문 기록 넓히기 — 페이지 간 이동·탭/칩/펼침 클릭 (2026-11-13)

대표 요청 ⑤⑥. UI 개선(메뉴 개편·찾아보기·검색 화면·브리프 카드)의 효과를 재기 위한 익명 하루 카운터.
구현: migration `154_rum_nav_ui_events.sql` + `web/templates/base.html` 의 `[154]` 스크립트.

## 1. 왜

| 묻고 싶은 것 | 지금 있는 것 | 빈 곳 |
|---|---|---|
| 용어 페이지에서 어디로 가나, 검색 화면을 거쳐 문서로 가나 | RUM(072~083, Cloudflare) 페이지별 방문 수 | 페이지 **사이** 이동 없음 |
| 찾아보기·검색 필터·탭을 실제로 누르나 | 없음 | 클릭 없음 |
| 483 카드 "Observation 상세"를 몇 번 펼치나(⑥) | 없음 | 펼침 없음 |

Cloudflare 비콘은 사용자 이벤트를 싣지 못하고, 퍼널 카운터(060·076·084·087)는 구독 제출 전용이다.

## 2. 무엇을 세나

**이동** `rum_nav_daily(snap_date, lang, from_kind, to_kind, total)`
- 페이지가 열릴 때 1. `from_kind` = 같은 사이트 리퍼러의 페이지 종류, 바깥·직접 유입은 `entry`.
- 새로고침은 세지 않는다(`performance` navigation type = reload). 뒤로 가기는 이동으로 센다.

**클릭·펼침** `rum_ui_daily(snap_date, lang, page_kind, ui_kind, ui_id, ctx, total)`
- `ui_kind` 다섯 값:
  - `expand`: details 열기, 닫기는 세지 않는다.
  - `tab`: 역할이 tab 이거나 aria-selected, 또는 클래스에 tab.
  - `chip`: aria-pressed 이거나 클래스에 chip/pill.
  - `toggle`: aria-expanded 이거나 클래스에 toggle.
  - `filter`: 라디오·체크박스·select 변경.
- `ui_id` = 요소의 CSS 클래스 이름. 상태·아이콘 클래스를 뺀 앞 두 개(예: `block-detail`, `qz-chip`)이고, 클래스가 없으면 조상 3단까지 올라가 찾는다.
  - 필터는 묶음의 id(예: `sr-f-agency`)를 쓴다.
- `ctx` = 카드 안이면 카드 종류(영문 slug, 예: `fda-483`), 아니면 빈 값.
- **⑥ 483 펼침** = `page_kind=brief · ui_kind=expand · ui_id=block-detail · ctx=fda-483`. 판독 함수에 날짜별 키(`expand_483_by_day`)를 따로 두었다.
- 반응 버튼(하트·스크랩, 이미 따로 셈)·상단 메뉴·헤더 검색·푸터는 뺀다.

**페이지 종류**는 경로 앞 두 조각을 화이트리스트로 접은 이름이다.

| 경로 | 종류 |
|---|---|
| `/` | home |
| `/briefs/<날짜>/` | brief |
| `/archive/` | archive |
| `/glossary/` | glossary |
| `/glossary/<용어>/` | term |
| `/findings/` | findings |
| `/findings/<하위>/` 목록 | findings-<하위> |
| `/findings/<하위>/<항목>/` 상세 | <하위>(doc·firm·clause·category …) |
| search·browse·guide·library·quiz·news·me·about 등 | 그대로 |
| 그 밖 | other |

`/en/` 은 lang 열로 가른다.

## 3. 개인정보 — 싣지 않는 것

- 경로·쿼리·검색어·업체명·사람 이름·문서 id·고른 필터 값·화면 글자를 싣지 않는다. 종류는 화이트리스트 이름이라 업체 slug 나 문서 id 가 들어갈 자리가 없다. 실사관 이름은 원래 쿼리(`?key=`)에만 있다(084 의 근거와 같음).
- 개인·세션 식별자, 분 단위 시각이 없다. 키는 날짜(KST)와 위 어휘뿐이라 한 사람의 행동을 이어 볼 수 없다.
- 클라이언트가 틀려도 DB 가 막는다.
  - 형식 `^[a-z][a-z0-9-]{0,23}$`(ui_id 는 39자)에 맞지 않으면 `other` 로 접는다. 실측에서 한글 이름은 `other` 가 됐다.
  - 하루 새 행 상한은 이동 600·클릭 800이고, 넘치면 그 튜플을 `other` 로 접는다.
  - 모르는 ui_kind 는 예외로 처리한다.
- 보내지 않는 경우: 운영자(`grm-op`)·자동화 브라우저·프리뷰 호스트·/admin. RUM 비콘·퍼널과 같은 게이트다.
- 한 페이지에서 보내는 수는 60건까지다.
- 영문 페이지에 한글을 내지 않는다. 카드 종류 표의 한글 키는 `\u` 이스케이프로 적었다.

## 4. 봇·기존 배관과의 정합

- `rum_nav_daily_clean` · `rum_ui_daily_clean` 은 139 `rum_anomaly_days`(봇 폭주일)를 같은 방식으로 뺀다. 분석·보고는 `_clean` 만 읽는다(139 규율). 판독 함수 `rum_ui_report(from, to)` 도 `_clean` 만 읽는다.
- 날짜는 KST 로 072 와 같다. `rum_daily_clean` 방문 수와 같은 날로 맞춰 "방문당 펼침" 같은 비율을 낼 수 있다.
- Cloudflare RUM 은 표본이고 이 카운터는 전수다. 비율을 낼 때는 이 차이를 감안한다.
- 기존 표·보기·함수는 바꾸지 않았다. 가산만 했다.

## 5. 쓰는 법

```sql
select jsonb_pretty(public.rum_ui_report(date '2026-11-14', date '2026-11-27'));
```
- `nav_top`: 많이 쓰인 이동 60개. 예: `term → doc`, `search → doc`, `entry → brief`.
- `ui_top`: 많이 눌린 요소 80개.
- `expand_483_by_day`: ⑥.
- `excluded_days`: 봇으로 뺀 날.
- `first_day`: 관측 시작일(소급 불가).

## 6. 적용·배포 순서

1. migration 154 를 적용한다(비서실, 대표 승인 뒤).
2. base.html 을 배포한다. 반대 순서여도 fetch 실패는 조용히 버려져 화면은 무사하지만, 그 사이 기록은 없다.

## 7. 한계

- 소급할 수 없다. 개선 전 기준선은 적용일부터 쌓인다. 개선을 배포하기 1~2주 전에 적용해야 비교가 된다.
- 요소 이름이 클래스라 클래스 이름을 바꾸면 그 요소의 기록이 새 이름으로 갈린다. 판독 때 이름 대조가 필요하다.
- 앱 내장 브라우저처럼 리퍼러를 보내지 않는 환경은 `entry` 로 잡힌다(087 실측과 같은 한계).
