# 편집팀 3분리 — 시범 지시문

현행 월요일 발행 Routine 은 `docs/prompts/GRM_Prompt_v16.md` 하나가 선별·작성·자가 점검·마감을 한 번에 한다.
여기 지시문은 그 일을 **데스크 → 기자 → 교열** 세 세션으로 나눈다. 시범 기간(2026-W45·W46)에는
실제 발행을 그대로 두고 **그림자 실행**(`SHADOW.md`)으로만 돈다.

## 원칙 — v16 을 베끼지 않는다
직무 지시문은 v16 본문을 옮겨 적지 않고 **"v16 의 어느 절을 따르라"만 가리킨다.**
옮겨 적으면 줄이 빠지거나 바뀌어 품질이 떨어진다. v16 이 고쳐지면 세 직무에 그대로 반영된다.
`tests/test_company_editorial_coverage.py` 가 v16 §B 의 모든 절이 어느 직무에든 배정됐는지 CI 에서 확인한다
(v16 에 새 절이 생기면 배정할 때까지 CI 가 실패한다).

| 직무 | 모델 | 시각 (그림자, KST) | 맡는 일 |
|---|---|---|---|
| 데스크 | Sonnet | 월 13:00 | handoff 읽기 · row 별 조치 배정 · 검색 보강 |
| 기자 | Opus | 월 14:00 | 산문 슬롯(국·영문) · tldr · 심층분석 |
| 교열 | Sonnet | 월 15:30 | 발행 게이트 코드 실행 · 기준표 O/X 판정 |

기자를 Opus 로 두는 이유: 현행 Routine 과 같은 모델이어야 품질 차이가 "나눈 효과"만 남는다.
기자 모델을 낮추는 것은 3분리가 통과한 뒤 따로 시험한다.

사용량이 1.3배 이내**면 전환한다. 하나라도 나쁘면 고쳐서 2주 더 보거나 접는다.
