## 1. 왜 하는가 · 왜 안 하는가 (기대치 고정)

### 하는 이유
- 지적사항 **92%가 원문이 이미 영어**다(§2.1). 영문판은 새 번역이 아니라 **덧씌운 한국어
  층을 걷어내는 일**이다.
- 8개 규제기관을 하나의 분류 체계로 정규화한 것 + 무료·공개는 유료 경쟁 제품이 못 갖는다.
- **식약처 데이터를 영어로 내는 곳은 없다**(Redica·FDAzilla 모두 한국 데이터 미취급).
  이것이 유일하게 남이 못 하는 자산이다.

### 기대하면 안 되는 것
- **유입은 안 는다.** 모르는 사람이 수천 명에서 수십만 명으로 늘 뿐이다. 유통은 따로 풀어야
  한다(2026-09-03 실측: 주 265 방문·구독 8명·전환 0.9%는 정상, 병목은 유입 규모).
- **도메인 나이 문제는 그대로다.** 홈에 `Weekly News Vol. 11` — 약 3개월. 영어 검색은
  한국어보다 경쟁이 심하다.
- 영문판은 **성장 대책이 아니라 자산을 넓게 쓰는 일**로 잡아야 한다.

## 3. 언어 선택 UI — 어떻게 만드는가

### 원하는 모습
```
화면 우상단  [한국어 ▾]  →  누르면 English 선택
주소         grm-solutions.com/findings/doc/xxx/     (한국어)
             grm-solutions.com/en/findings/doc/xxx/  (영어)
```

애플·삼성 등 글로벌 사이트가 `/kr/`·`/us/`·`/jp/` 를 쓰는 것과 같은 구조다.

### ★반드시 지킬 것
- **주소를 나눈다.** 버튼만 눌러 화면 글자를 바꾸고 주소가 그대로면, 구글에는 **여전히
  한국어 페이지 하나**다. 영어 검색에 영영 안 잡힌다 — 만드는 목적 자체가 사라진다.
- **`hreflang` 을 서로 걸어준다.** 두 페이지가 "같은 내용의 다른 언어판"임을 알린다.
  없으면 구글이 중복 페이지로 보고 한쪽을 버릴 수 있다.
- **정적 생성이라 오히려 쉽다.** 이미 4,000장을 미리 만들고 있으므로 `/en/` 은 출력
  디렉터리가 하나 더 생기는 구조다. 실시간 전환이 필요 없다.

### 권장 순서
1. `render.py` 의 경로 하드코딩 42곳을 **경로 계산 함수 하나로 모은다**(언어 접두 인자를 받게).
   이것이 이 작업의 8할이다. 나머지는 이 함수 위에 얹힌다.
2. 문구 사전(약 960개)을 한 곳에 모은다. 지금은 JS·템플릿에 흩어져 있다.
3. `/en/` 트리 렌더 → `hreflang` → 언어 선택 UI → 사이트맵·도달성 가드 갱신.

## 4. 브리프 영문 발행 (운영자 정정 반영)

### ★2026-09-03 세션이 틀렸던 것
이 세션은 처음에 **"브리프는 매주 사람이 쓰는 글이라 영문판은 영구히 2배 노동"** 이라
판단하고 범위에서 뺐다. **이 판단은 틀렸다.** 운영자 정정:

> 브리프는 지금도 **원문을 요약·정리한 것**이다. 그리고 그걸 한국어로 낸다.
> 영문은 **요약·정리한 것을 그대로 내면 된다** — 번역 단계가 빠지는 것뿐이다.

### 실제 구조 (2026-09-03 최신 브리프 `brief_web_2026_08_31.json` 실측)

```
원문(영어) ──► Routine 이 요약·정리 ──► 한국어로 출력 ──► 브리프
                                    └─► (영문판) 그대로 출력   ← 추가할 갈래
```

카드 21장의 필드 실측:

| 필드 | 언어 | 비고 |
|---|---|---|
| `title_issue`·`summary`·`implication`·`key_facts`·`checks` | 한국어 | **Routine 이 생성** — 영문 갈래가 필요한 곳 |
| `deterministic_detail` | **원문·국문 병기** | `action`/`action_ko`, `nature`/`nature_ko`, `operations`/`operations_ko` … **이미 영문 보유** |
| `quotes[].original` | **영어 원문** | 20/21 카드 보유 |
| `card_type`·`type_tag`·`group_label`·`modality` | 한국어 라벨 | 사전 치환으로 해결 |
| `facts[].label` | 한국어 라벨 | 사전 치환 |
| `agency`·`publish_date`·`window` | 언어 무관 | 그대로 |

**결론**: 카드 21장 중 16장이 `deterministic_detail` 로 이미 영문 본문을 갖고 있고, 20장이
영어 인용문을 갖고 있다. **새로 만들어야 하는 것은 서사 5개 필드뿐이다.**

### 발행 계획 (운영자 지시)
- **다음 주 발행부터 영문 브리프를 같이 낸다**(전향적).
- **기존 발행분 소급(백필)은 별도 트랙.** 공수가 크고 급하지 않다. 안 해도 된다.
  - 소급 대상은 현재 `web/data/briefs/` 의 발행분 전체
  - 소급하려면 과거 카드의 원문을 다시 확보해야 하는 것들이 있어 비용이 더 든다

### ★반드시 지킬 것 — 지어내지 않기
이 저장소는 **생성물이 원문을 왜곡하지 않는 것**을 아주 강하게 지킨다. 영문 요약을
추가한다는 것은 생성 경로를 하나 더 만드는 일이므로, 기존 규율을 그대로 물려받아야 한다.

- `verify_deep_analysis.py` 의 근거 대조 게이트(D2 조항 인용·D4 축자·D5b 절단)가 본보기다.
- `quotes[].original` 은 **리터럴 금지**(본문 슬라이스로 생성) — 기존 계약.
- 영문 요약도 **원문에 있는 말만** 쓰게 하고, 그것을 검사하는 게이트를 같이 만든다.
- 한국어판과 영문판이 **서로 다른 사실을 말하면 안 된다**(같은 원문에서 나왔으므로).
  두 판의 사실 일치를 검사하는 가드를 권장한다(숫자·날짜·업체명 대조).

## 6. ★함정 (이 저장소가 반복해서 데인 자리)

새 세션이 같은 곳에 빠지지 않도록 남긴다.

1. **조용한 0장.** `_load_reg_ref_catalogs()` 는 ich/eu_gmp/pics/who/mfds 만 싣고 **cfr 은
   안 싣는다.** 모르고 `.get("cfr")` 를 썼더니 페이지가 0장이 됐는데 **렌더는 성공으로
   끝났다.** 새 데이터 소스를 쓸 때는 "비면 실패" 가드를 같이 만들 것.
2. **0장인 상태로 골든을 동결하면 그게 정답이 된다.** 위 버그를 고치기 전에 동결해
   사이트맵이 조항 페이지를 안 담았다. **동결 전에 산출물 개수를 눈으로 확인할 것.**
3. **`exit=$?` 를 믿지 마라.** `python -m unittest ... | tail; echo exit=$?` 는 **tail 의
   종료코드**를 찍는다. 900초 timeout 에 끊겼는데 `exit=0` 이었다. **`Ran N tests` 와 `OK`
   줄을 직접 확인할 것.** 이 세션에서 두 번 걸렸다.
4. **env 전달 ≠ 배선.** `grm-intake.yml` 은 플래그를 하나씩 열거해 넘긴다. 코드가 읽는
   플래그 이름이 그 목록에 없으면 repo 변수를 켜도 전달되지 않는다(`ENABLE_MHRA_ALERT_BODY`
   가 8월 26일부터 그 상태였다). **이 저장소에서 3회차 사고.**
5. **계약 테스트가 깨지는 게 정상일 때가 있다.** 뷰모델 dict 형태를 고정한 테스트는
   키를 추가하면 깨진다. **통과시키려 무르게 고치지 말고 계약을 갱신**하고 이유를 주석에 남길 것.
6. **Windows 로컬은 `PYTHONUTF8=1` 필수.** em-dash·한글이 cp949 stdout 에서 죽는다.
7. **로컬 전체 스위트는 10~16분.** CI 가 최종 게이트다. 로컬은 targeted 로 좁혀 돌릴 것.
8. **`gh pr merge` 가 "'main' is already used by worktree" 로 실패해도 원격 머지는 완료된다.**
   반드시 `gh pr view <n> --json state` 로 재확인.
9. **작업은 격리 worktree 에서.** 다른 세션이 같은 저장소를 쓴다. 다른 `_wt-*` 를 건드리지 말 것.

## 7. 착수 순서 제안

```
1단계  경로 계산 함수 통합(42곳)          ← 이게 8할. 여기만 하면 나머지는 쉽다
2단계  문구 사전 추출(약 960개)
3단계  /en/ 트리 렌더 + hreflang + 언어 선택 UI
4단계  findings_docs.json 에 영문 원문 추가(+8.5MB)   ← 3단계에서 실제로 필요해지면
5단계  영문 브리프 갈래(서사 5개 필드) + 사실 일치 가드
6단계  도달성 가드·사이트맵·골든 갱신
```

**1단계만 끝나도 가치가 있다** — 경로가 한 곳으로 모이면 이후 어떤 트리를 얹든 쉬워진다.
**3단계까지 하면 지적사항 DB 영문판이 서고**, 5단계는 그 뒤에 판단해도 늦지 않다.
