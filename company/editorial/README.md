# 편집팀 — 월요일 브리프 (데스크 → 기자 → 교열)

예전에는 `docs/prompts/GRM_Prompt_v16.md` 하나가 선별·작성·자가 점검·마감을 한 Routine 안에서 다 했다.
2026-W45 부터는 편집팀 세 직무가 나눠서 하고, 현행 v16 Routine 은 **백업**으로 남는다. 실행 규칙은 `RUN.md`.

## 원칙 — v16 을 베끼지 않는다
직무 지시문은 v16 본문을 옮겨 적지 않고 **"v16 의 어느 절을 따르라"만 가리킨다.**
옮겨 적으면 줄이 빠지거나 바뀌어 품질이 떨어진다. v16 이 고쳐지면 세 직무에 그대로 반영된다.
`tests/test_company_editorial_coverage.py` 가 v16 §B 의 모든 절이 어느 직무에든 배정됐는지 CI 에서 확인한다
(v16 에 새 절이 생기면 배정할 때까지 CI 가 실패한다).

| 직무 | 모델 | 월요일 (KST) | 맡는 일 | Notion |
|---|---|---|---|---|
| 데스크 | Sonnet | 05:30 | handoff 읽기 · row 별 조치 배정 · 검색 보강 | 읽기만 |
| 기자 | Opus | 06:10 | 산문 슬롯(국·영문) · tldr · 심층분석 | 읽기만 |
| 교열 | Sonnet | 07:40 | 발행 게이트 코드 · 기준표 판정 · **전부 통과면** 예치·마감 | 통과 시에만 |
| 백업 (현행 v16 Routine) | Opus | 09:30 | handoff 가 아직 OPEN 이면 예전 방식 그대로 발행 | 평소대로 |

기자를 Opus 로 두는 이유: 현행과 같은 모델이어야 글 품질이 낮아지지 않는다. 낮추는 시험은 따로 한다.

## 왜 품질이 떨어질 수 없나
- 교열이 **발행 게이트 코드 통과 + 기준표 위반 0** 일 때만 발행 경로에 넘긴다.
- 그 밖의 모든 경우(어느 직무든 실패·지연·보류)엔 Notion 에 아무것도 쓰지 않는다 →
  handoff 가 OPEN 으로 남아 09:30 백업이 예전 방식으로 발행한다.
- 발행 브릿지는 월 07:07~13:37 KST 에 30분마다 예치를 확인하므로 백업이 09:30 에 돌아도 그날 발행된다.
- 어느 쪽이 발행하든 마지막엔 대표가 관리자 사이트에서 미리보기를 보고 승인한다.
