# GRM 주간 퀴즈 생성 프롬프트

- 예약 태스크: `grm-monday-quiz-gen`
- 실행 시각: 매주 월요일 13:00 KST
- 정본 문항 뱅크: `web/data/quiz_bank.json`
- 무인 게이트: `quiz_lint.py`
- 문서 버전: **v2 (2026-08-04)** — 세트 구성·개념 문항·소재·선택지 길이 규율 신설. 파일명의 `_v1` 접미사는 예약 태스크가 경로로 이 문서를 참조하므로 유지한다(경로가 바뀌면 세션이 더 약한 규율로 조용히 폴백한다).
- 이 문서는 예약 세션이 따라야 할 단일 정본이다. 다른 대화의 지시나 과거 초안으로 규율을 완화하지 않는다.

## 1. 완료 목표

그 주에 라이브 공개된 최신 브리프 카드와 공개 용어사전에서 3~4문항(기본 4문항)을 만들고 정본 뱅크에 append한다. **한 세트는 브리프 사건 문항과 개념 문항을 함께 담는다**(§3.2). 모든 신규 문항은 해당 ISO 주차의 `week` 키를 가지며, 기계 검증과 전체 CI가 green인 경우에만 PR을 직접 머지한다. 후보를 충분히 검증할 수 없으면 억지로 채우지 말고 그 주 실행을 스킵한다.

> **왜 v2 인가.** v1 규율은 "그 주 카드에 명시된 사실만"을 요구했고, 그 결과 3주 연속(202630·202631·202632) 노출 세트 12문항이 **전부 브리프 암기**가 됐다. 그 주 브리프를 읽지 않은 직원에게는 4문항 전부가 찍기이고, 용어사전 226어 중 출제된 것은 21어(9.3%)에 머물러 GMP·일탈·CAPA 같은 기초 개념이 한 번도 나오지 않았다. 같은 기간 "가장 긴 선택지 찍기" 전략의 기대 정답률은 76.4%였다(무작위 25%).

## 2. 시작 전 선행 조건

1. `git fetch --prune origin` 후 `origin/main`에서 전용 브랜치와 clean worktree를 만든다. 기존 dirty 파일을 가져가거나 다른 작업자의 worktree를 수정하지 않는다.
2. 실행 시각의 KST 날짜로 ISO 주차 `YYYYWW`를 계산한다. 예: 2026년 ISO 29주차는 `202629`.
3. `web/data/quiz_bank.json`에 동일한 `week`가 하나라도 있으면 이미 처리된 주다. 파일을 수정하거나 새 PR을 만들지 말고 `SKIP duplicate-week: YYYYWW`로 종료한다.
4. 최신 `web/data/briefs/*.json`이 `origin/main`에 있고, 그 `brief.publish_date` 페이지와 카드 앵커가 `https://grm-solutions.com/briefs/{publish_date}/#{card.id}`에서 라이브인지 확인한다. 라이브가 아니거나 최신 발행본을 확정할 수 없으면 스킵한다.
5. 입력은 다음으로 제한한다. 검색 결과·기억·비공개 브랜치·Notion staging을 정답 근거로 쓰지 않는다.
   - `web/data/briefs/*.json` — 최신 라이브 브리프(브리프 문항의 유일 근거)
   - `web/data/glossary.json` — 공개 용어사전(개념 문항의 유일 근거)
   - `web/data/library_updates.json` + `web/data/library/*.json` — 그 주 자료실 신규·변경 자료(개념 문항의 **주제 선정**에만 쓴다. 카탈로그는 제목·발행일·원문 링크만 담고 본문이 없으므로 자료실 내용을 묻는 문항은 만들 수 없다)

## 3. 출제 규율

### 3.1 주차와 ID

- 신규 문항마다 문자열 `week: "YYYYWW"`를 반드시 넣는다.
- ID는 `q-{YYYYWW}-{NN}` 형식으로 만든다. `NN`은 01부터 시작하며 전체 뱅크에서 고유해야 한다.
- 기존 문항은 수정·재정렬하지 않고 신규 문항만 배열 끝에 append한다. 이미 공개된 ID와 `week`는 불변이다.

### 3.2 주차 세트 구성 (최상위 규율)

한 주 세트는 **성격이 다른 두 종류**를 함께 담는다. 4문항 기준 구성은 다음과 같다.

| 종류 | 수 | `source_type` | 근거 |
|---|---|---|---|
| 브리프 사건 문항 | 2 (최대 3) | `brief` | 그 주 라이브 브리프 카드 앵커 |
| 개념 문항 | **1~2 (최소 1)** | `glossary` | `glossary.json`의 용어 `id` |

- **개념 문항이 하나도 없는 세트는 만들지 않는다.** 그 주 브리프를 읽지 않은 사람에게 전 문항이 찍기가 되기 때문이다. 기계 게이트 `WEEK_SOURCE_MIX`가 이를 막는다.
- 3문항만 확보되면 개념 1 + 브리프 2로 구성한다. 개념 문항을 못 만들면 세트를 만들지 말고 §5로 스킵한다.
- 5문항 이상 만들지 않는다. 클라이언트(`web/assets/quiz.js`)가 이번 주 세트를 4문항으로 자르므로 초과분은 **어떤 주에도 화면에 뜨지 않는다**. 기계 게이트 `WEEK_SIZE`.

### 3.3 브리프 사건 문항

- `source_ref`는 최신 라이브 브리프의 정확한 카드 앵커다.
- 한 문항의 질문·정답·해설은 한 카드에 명시된 사실만으로 완결되어야 한다.
- 같은 카드에서 여러 문항을 만들지 않는 것을 원칙으로 한다. 불가피하면 서로 다른 명시 사실을 묻고 복수정답 가능성이 없음을 각각 확인한다.
- 업체명·조치·지적사항·회수 사유·명시된 법조항처럼 카드에서 그대로 대조 가능한 사실을 우선한다. 카드가 말하지 않은 인과, 위험도, 업계 일반론을 추론해 정답으로 만들지 않는다.
- 질문문에 "…카드에서"라고 쓰지 않는다. 사건 자체(업체·조치·지적)를 주어로 삼아 카드를 읽지 않은 사람도 무엇을 묻는지 알 수 있게 한다. 출처는 채점 후 근거 링크가 보여준다.

### 3.4 개념 문항 (용어사전)

- `source_type`은 `glossary`이고 `source_ref`는 `glossary.json`의 `id`다(URL이 아니다).
- 정답은 그 용어의 `easy_ko`(쉬운 풀이)에 명시된 내용으로 한정한다. `detail_ko`(실무 맥락)와 `reg_refs`(관련 조항)는 `explanation_ko`의 재료로 쓴다.
- **오답은 그 용어의 `related` 목록 또는 같은 주제 축의 다른 표제어 정의에서 뽑는다.** 다른 축에서 뽑으면(무균공정 문항에 데이터 백업 선택지) 지문을 읽지 않아도 소거된다 — §3.6.
- 이미 출제된 용어는 재출제하지 않는다. 뱅크에서 `source_type == "glossary"`인 항목의 `source_ref` 집합을 먼저 모으고, `aliases`가 같은 개념을 가리키는 경우도 같은 용어로 본다.
- **용어 선정 우선순위**
  1. 그 주 자료실 신규·변경 자료가 다루는 주제. `web/data/library_updates.json`의 최신 `entries[0]`에서 `new_ids`·`changed_ids`를 읽고, `web/data/library/<source>.json`에서 그 id의 `title_ko`/`title_en`을 찾아 주제를 파악한 뒤 대응하는 용어를 고른다. (예: `pics-pi-006-4` = Validation Master Plan → `validation-master-plan` 계열 용어)
  2. 미출제 용어 중 실무 빈출 기초 개념 — GMP, 일탈, CAPA, 변경관리, 밸리데이션, 자율점검, 품질부서 책임 등.
  3. 그 주 브리프 카드가 실제로 건드린 개념(사건 문항과 짝이 되어 "무엇이 문제였고 그 개념이 무엇인지"가 한 세트에서 이어진다).
- 자료실 자료의 **내용**을 묻지 않는다. 카탈로그에는 제목·발행일·원문 링크만 있고 본문이 없다. "이번 주 자료실에 추가된 문서는?"처럼 제목을 외우게 하는 문항은 §3.5 금지 대상이다.

### 3.5 소재 게이트

- 출제 대상은 **사람용 의약품(완제·원료)의 GMP·품질·규제 준수**다.
- 다음이 단독 소재이면 출제하지 않는다: 의약외품, 화장품, 식품·건강기능식품, 의료기기, 담배·니코틴 제품, 동물용의약품.
- **순수 수치 회상 문항을 만들지 않는다.** "몇 개인가요", "며칠에 열렸나요"처럼 카드의 숫자만 외우면 되는 문항은 학습 가치가 없다. 다만 그 수치가 규제 판단의 핵심일 때(업무정지 기간, 기준치 초과 여부, 인용 조항 번호)는 허용한다.
- 소재 게이트를 지키며 브리프 문항 2건을 확보하지 못하면 그 주는 개념 문항 비중을 늘리지 말고 §5로 스킵한다.

### 3.6 내부 개념 금지

- GRM 자체, Evidence Level, Signal Tier/Tier 1~3, 듀얼 링크, intake, handoff, scaffold, delta bridge, Notion, Supabase, PostgREST/RLS, `source_ref`, `answer_index`, `render_order`, lint 코드 등 운영·구현 개념을 묻지 않는다.
- 금지어의 기계 정본은 `quiz_lint.py`의 `INTERNAL_CONCEPT_PATTERNS`다. 표현을 바꿔 우회하지 않는다.
- 공개 규제·품질 개념인 GMP, CAPA, OOS, 무균공정, 실제 지적 내용 등은 근거가 명시되면 출제할 수 있다.

### 3.7 정답과 근거 명시성

- 네 선택지 중 정답은 정확히 하나여야 하며 `answer_index`는 0~3의 정수다.
- `explanation_ko`는 1~2문장으로, 왜 정답인지와 어느 명시 사실·정의에 근거하는지 설명한다.
- 고유명사, 수치, 날짜, 기간, 등급, 법조항은 근거 텍스트에 그대로 있을 때만 사용한다.
- 브리프 문항은 카드 밖의 법령 지식·상식·검색·번역 추론이 필요하면 폐기한다. 개념 문항은 그 용어 항목 밖의 지식이 필요하면 폐기한다.

### 3.8 오답 비왜곡과 소거 불가능성

- 오답은 실제 업체·규제 문서·품질 개념을 짧은 명사구로 제시할 수 있으나, 존재하지 않는 사건이나 허위 사실을 완전한 문장으로 단정하지 않는다.
- 카드의 다른 사실을 섞어 가짜 인과관계·가짜 조치·가짜 위반을 만들지 않는다.
- 일부 조건에서는 맞을 수 있는 선택지, 정답의 상·하위개념, 동의어, 중첩 조합은 제외한다.
- 부정형·함정형 질문, "모두 고르시오", 복수정답형은 금지한다.
- **선택지 4개는 모두 같은 주제 축에 있어야 한다.** 셋 중 둘 이상이 명백히 다른 영역이면 지문을 읽지 않아도 소거되므로 폐기한다.
- **자기 점검(필수):** 질문문을 가리고 선택지 4개만 놓고 봤을 때 정답을 고를 수 있으면 그 문항은 폐기한다.
- 좋은 오답의 본보기는 `q2-b09`다 — 같은 카드에 **실재하는 다른 관찰사항 3건**을 오답으로 썼다. 사실을 지어내지 않으면서 넷 다 그럴듯하다.

### 3.9 선택지 길이

- 정답이 오답 중 최장보다 **12자 이상 길면 안 된다**. 길이만 보고 고를 수 있기 때문이다. 기계 게이트 `ANSWER_LENGTH_LEAD`.
- 한 주 세트에서 "정답이 유일 최장 선택지"인 문항이 **과반이면 안 된다**. 기계 게이트 `WEEK_LONGEST_ANSWER`.
- 맞추는 방법은 **오답을 정답과 같은 밀도로 채우는 것**이다. 정답을 흐리거나 잘라서 줄이지 않는다 — 정확성이 길이보다 우선이고, 정답을 훼손해야만 통과되는 후보는 폐기 대상이다.

### 3.10 구성

- 주당 3~4문항, 기본 4문항이다(§3.2).
- `normal`은 1~2문항이고 `easy`는 `normal`보다 적을 수 없다. `hard`는 사용하지 않는다. 기계 게이트 `WEEK_DIFFICULTY_MIX`.
- 난이도는 출처가 아니라 **체감 난이도**로 매긴다. 용어 정의를 그대로 묻는 문항은 `easy`, 두 개념의 구분이나 조항 대응을 묻는 문항은 `normal`이다.
- 질문문 정규화 결과, 정답, `source_ref`와 묻는 사실이 기존 문항과 중복되면 폐기한다. 표현만 바꾼 재출제도 중복이다.

## 4. 검증·PR·머지 절차

1. 변경 직후 `python quiz_lint.py`를 실행한다. stdout 첫 줄이 `quiz_lint: PASS`이고 exit 0이어야 한다.
2. `python -m unittest tests.test_quiz_lint -v`를 실행한다.
3. `python -m unittest discover -s tests -v`로 전체 테스트를 실행한다. 저장소가 지정한 별도 필수 검사가 있으면 함께 실행한다.
4. 실패 원인이 문항에 있으면 해당 후보를 수정하거나 폐기한다. **검증 규칙·금지어·테스트·면제 목록(`GRANDFATHERED_WEEKS`)을 완화하거나 늘려 문항을 통과시키지 않는다.**
5. 의도한 `web/data/quiz_bank.json` 변경만 명시적으로 stage하고, diff에서 기존 문항 변형·재정렬·무관 파일을 확인한다.
6. `codex/quiz-week-{YYYYWW}` 브랜치를 push하고 PR을 만든다. PR 본문에는 주차, 문항 수, **세트 구성(브리프 N + 개념 N)**, 근거 카드 ID와 용어 ID, lint/전체 테스트 결과를 적는다.
7. 필수 GitHub Actions가 모두 성공할 때까지 확인한다. CI red면 로그의 첫 실제 실패를 고쳐 같은 브랜치에 push하고 다시 확인한다.
8. 필수 check가 모두 green이고 merge 가능할 때만 PR을 직접 머지한다. 머지 뒤 `origin/main`에 반영됐는지 확인하고 전용 worktree를 제거한다.

### 4.1 세트 단위 게이트 코드

문항 하나하나는 멀쩡해도 세트로 묶였을 때 드러나는 결함이 있다. 다음 코드가 뜨면 세트 구성을 고친다.

| 코드 | 의미 |
|---|---|
| `WEEK_SOURCE_MIX` | 세트에 개념 문항(`glossary`)이 없다 — §3.2 |
| `WEEK_SIZE` | 세트가 3~4문항이 아니다 — §3.2 |
| `WEEK_DIFFICULTY_MIX` | `normal`이 1~2가 아니거나 `easy`가 `normal`보다 적다 — §3.10 |
| `WEEK_LONGEST_ANSWER` | 세트 과반에서 정답이 유일 최장 선택지다 — §3.9 |
| `ANSWER_LENGTH_LEAD` | 정답이 오답 최장보다 12자 이상 길다 — §3.9 |

## 5. 스킵 조건

다음 중 하나면 파일·브랜치·PR을 남기지 않고 `SKIP <reason>`과 확인한 주차·최신 브리프·실패 후보 ID를 stdout 보고에 남긴다.

- 동일 `week`가 이미 존재함
- 최신 브리프가 아직 `main` 또는 라이브 사이트에 없음
- 브리프 날짜·카드 ID·공개 앵커가 서로 불일치함
- **개념 문항을 1건도 확보하지 못함**(미출제 용어가 없거나 근거가 불충분함)
- 소재 게이트(§3.5)를 지키며 브리프 문항 2건을 확보하지 못함
- 근거가 명시적인 유일정답 문항을 최소 3개 확보하지 못함
- 내부 개념 금지 또는 오답 비왜곡 규율을 지키며 후보를 만들 수 없음
- `quiz_lint.py` 또는 전체 테스트를 합리적으로 수정 가능한 문항 변경만으로 green으로 만들 수 없음
- GitHub 인증·보호 규칙·외부 CI 장애·merge conflict로 안전한 무인 머지가 불가능함

스킵은 실패 은폐가 아니다. 게이트를 우회하거나 지난주 문항을 새 `week`로 복제하는 것보다 올바른 완료 상태다.

## 6. 실행 종료 보고

성공 시 `DONE YYYYWW`와 문항 ID, 세트 구성(브리프 N + 개념 N), 근거 카드 ID·용어 ID, 커밋 SHA, PR URL, CI 결과, merge SHA를 남긴다. 스킵 시 `SKIP YYYYWW`와 단일 주원인, 확인한 근거, 생성했으나 폐기한 후보 ID를 남긴다. 어느 경우든 사람이 이전 commentary를 읽지 않아도 결과를 판단할 수 있는 독립 보고여야 한다.
