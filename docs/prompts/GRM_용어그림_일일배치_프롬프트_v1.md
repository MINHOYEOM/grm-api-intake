# GRM 용어 그림 일일 배치 — 실행 규율 v1 (2026-09-29)

예약작업 `grm-glossary-fig-daily`(매일, "지금 실행"으로 여러 번 돌려도 된다)가 이 문서를 **정본 규율**로
읽고 따른다. 목적은 두 가지다 — ① 그림이 없는 용어에 그림을 조금씩 채우고 ② 이미 있는 그림 중
정의와 안 맞는 것을 고친다.

**★이 배치의 성과는 그림 개수가 아니라 정직한 판정이다.** 한 회차에 새 그림 0장이 정상일 수 있다.
"오늘 몇 장"을 채우려는 압력이 억지 그림을 만든다 — 사용자 지적(2026-09-29): *"너무 억지로 그림을
만든다거나 안 맞는 경우도 있는 것 같다. 그런 건 특히나 조심해야 한다."* 그릴 구조가 정의에 없으면
그리지 않고 **그 판정을 장부에 남기는 것**이 이 배치의 정상 산출물이다.

## 구조(먼저 알 것)

- **그림은 한 벌뿐이다**: `web/partials/glossary_fig/<id>.html`(인라인 SVG). 사이트 용어 페이지, 링크드인
  카드 '이번 주 용어' 장(`linkedin_cards.mini`), GMP 용어집 PDF 가 **모두 이 파일을 렌더해 쓴다.**
  2026-09-29 전엔 카드에 사본(MINI_SVG)이 따로 있었고 9장이 갈라져 있었다 — 사이트에서 뺀 "Grade A"
  (무균조작)·"I·II·III 등급"(회수)이 카드에만 살아 있었다. **사본을 다시 만들지 마라.**
- **장부**: `web/data/glossary_fig_review.json` — `redo`(다시 그릴 그림, 사유) · `skip`(그리지 않기로 한
  용어, 사유). 테스트가 장부와 실제 파일이 어긋나지 않는지 본다(skip 인데 그림 있음 / redo 인데 그림 없음 → 빨강).
- **도구**: 루트 `glossary_figs.py` — `queue`(무엇을 먼저) · `check`(두 언어 × Pretendard 실측) ·
  `sheet`(정의와 나란히 놓은 검수 시트 PNG).

## 0. 선행 가드 — 걸리면 "스킵: <사유>"만 보고하고 끝낸다

1. 작업 위치는 상설 worktree `C:\Users\user\Desktop\Global Regulatory Sweep\_wt-glossary-fig`.
   없으면 `git -C "…\v15.0-implementation" worktree add ..\_wt-glossary-fig --detach origin/main` 로 만든다.
   `git status --porcelain` 이 비어 있지 않으면 **스킵**(앞 회차의 미완 산출물이다 — 지우지도 stash 하지도 말고
   무엇이 있었는지 보고한다).
2. `git fetch origin --prune`.
3. **열린 배치 PR**(`gh pr list --state open --search "head:glossary-fig/daily-"`)이 있으면 새로 만들지 않는다:
   - 모든 체크 SUCCESS(`gh pr view <n> --json statusCheckRollup` 로 conclusion 전부 확인) → 먼저 머지하고 계속.
   - 진행 중 → 끝날 때까지 기다린 뒤(최대 40분) 같은 판단. 실패 → 원인 한 줄 보고하고 **스킵**.
4. **다른 열린 PR 이 `web/data/i18n/en.json` 을 바꾸면 스킵** — 그 PR 과 이 배치가 영문 골든 5장의
   `i18n-en.js?v=` 줄을 서로 다르게 바꿔 둘 중 하나가 깨진다.
   `gh pr list --state open --json number,headRefName,files --jq '.[] | select(.headRefName | startswith("glossary-fig/") | not) | select(any(.files[]; .path == "web/data/i18n/en.json")) | .number'`
5. `git switch -C glossary-fig/daily-<YYYYMMDD-HHMM> origin/main`.

## 1. 이번 회차 대상

```
python glossary_figs.py queue --top 8
```

- **다시 볼 그림(redo)을 먼저**, 한 회차 **최대 2장**.
- 그다음 **새 후보를 목록 순서대로 최대 5개 판정**(카드에 자주 뜬 용어부터 나온다). 새 그림 **채택은 최대 3장**.
- 판정 결과가 '그리지 않음'이면 장부 `skip` 에 넣는다 — 이것도 이 회차의 성과다. 다음 회차가 같은 용어를 다시 보지 않는다.

## 2. 그릴지 판정 — 정의 문장에서 구조를 찾는다

근거는 **`easy_ko`·`easy_en` 정의 문장**이다(그 외엔 `definition_source` 가 **명시한** 구성 요소 이름만 —
예: 기준서 4종). 문장 안에 아래 구조 중 하나가 **있어야** 그린다:

| 구조 | 정의 속 신호 | 기존 예 |
|---|---|---|
| 눈금·한계 | 한도·범위·기준·규격을 넘음/안에 머묾 | oos · stability-testing · expiry-date |
| 경계·분리 | 분리·격리·독립·안/밖 | quarantine · quality-unit |
| 흐름·순서 | 정의가 단계를 **순서대로** 말함 | purified-water · finished-product · in-process-control |
| 전/후·대비 | 유지↔끊김, 전↔후, 뒤바뀜 | data-integrity · mix-up |
| 부분/전체 | 여러 개 → 하나, 묶어 부르는 이름 | batch-record · master-production-record |
| 인과·이동 | A 가 B 를 일으킴/옮김 | cross-contamination · hepa-filter |

- **없으면 그리지 않는다 → skip.** 사유는 정의에 기대어 쓴다(예: "정의가 '제조허가를 보유한 자' — 자격·주체라
  그림으로 옮길 구조가 없다").
- **아이콘 + 캡션**(문서·설비·용기 아이콘에 짧은 라벨)은 정의의 머리명사가 **구체물**(문서·설비·물질·조직)이고
  라벨 **2개 이하**가 그 용어만의 차이를 실어 나를 때만 허용한다.

## 3. 그리지 말아야 할 것 — A~H (★실제로 있었던 사례)

| | 금지 | 실례 |
|---|---|---|
| A | **정의 밖 주장** — 정의에 없는 수량·개수·번호·등급·비율·설비명·조건 | 무균조작 "Grade A"(카드 사본에만 남아 있었다) · 회수 "I·II·III 등급" · 유효성분 **반반 칠한 원**(=절반이 유효성분) · 공정 밸리데이션 **"배치 1·2·3"** · PQ **막대 3개**. 반복을 그려야 하면 **번호 없는 반복 표식 + 끝에 "…"** |
| B | **일하지 않는 요소** — 선·점선·화살표·막대는 반드시 무엇과 비교되거나 무엇을 잇는다 | 세척 밸리데이션 "잔류 한계" 점선이 두 상자 위를 지나가기만 함 |
| C | **뜻과 모순되는 기하** — 방향·위치·교차가 라벨 뜻과 어긋남 | 유효기간: 내려가는 품질선 **위에** 규격 한계 → 둘이 만나지 않는데 기간 끝을 찍음 |
| D | **글자 목록** — 순서·포함·비교 없이 정의 낱말 3개 이상을 상자·목록에 옮겨 적음. ★정의가 말하는 단계를 **순서대로 잇는 흐름은 구조다(D 아님)** | 품질시스템: 조직·책임/절차·공정/자원을 상자에 나열 |
| E | **억지 상징** — 뜻이 정해지지 않은 물결·"+"·별표가 개념을 대신함 | 유효성분 "약리작용" 물결 · 적격성평가/PQ 설비 상자의 "+" |
| F | **구별 불가** — 이름을 가리면 관련 용어 그림과 같음 | 적합기준 ↔ 공정 밸리데이션(범위 띠+점) · 무균조작 ↔ HEPA(여과 공기 화살표) · 영업자 회수 ↔ 회수 |
| G | **실무자가 보면 틀렸다/유치하다** | 엔도톡신: 화살표가 균 **전체**에서 "발열"로 나감 → 성분(LPS)이 아니라 균이 열을 내는 것으로 읽힘 |
| H | **판독성** — 카드 칸(150×88)에서 핵심 대비가 안 읽힘 | 혼동: 내용물 글자가 너무 흐려 뒤바뀜이 안 보였음(09-29 진하게) |

그리고 — 그림은 **정의를 묘사만** 한다(2026-09-08 원칙). 해설·실무 조언·예시 수치를 그림에 싣지 않는다.

## 4. 그리기 — 파일 형식

- `web/partials/glossary_fig/<id>.html`: 첫 줄에 Jinja 주석 `{#- 용어 그림 · <id> — 정의("…")를 무엇으로 옮겼나. 날짜 -#}`,
  이어서 `<svg class="gt-fig-svg" viewBox="0 0 W 88" role="img" aria-label="{{ _('한 줄 설명') }}">` 한 장.
  - `W` 는 150~184(영문 라벨이 길면 넓힌다). 높이 88 고정.
  - 색은 `style="fill:var(--coral)"` 식 CSS 변수, **다음 9개만**: `canvas card soft coral coral-2 coral-tint ink line-2 muted`
    (카드 팔레트 대응표 `linkedin_cards.MINI_COLORS` — 표에 없는 변수는 카드 렌더에서 KeyError 로 죽는다).
  - 라벨은 `{{ _('한국어') }}`, 글자 크기는 인라인 `font-size:8~10px`. 라벨 2~4개. ★영어는 한국어보다 길다 —
    **라벨을 세로로 쌓고 오른쪽에 글자**를 두면 폭이 남는다.
  - 기존 그림과 같은 결: 굵은 선 1.6~2.2, 둥근 모서리 rx 3~5, 강조는 coral/coral-2 한두 곳.
- `web/data/i18n/en.json`: 새 라벨·aria-label 키를 더한다(`json.dumps(d, ensure_ascii=False, indent=2, sort_keys=True) + "\n"`,
  LF). ★**키는 전역이다** — 같은 한국어 키가 이미 있으면 그 영어 값이 이 그림에도 맞는지 먼저 본다
  (`기준`="Ranking" 선례). 맞지 않으면 한국어 라벨을 바꾼다. 기존 값은 바꾸지 않는다.
- **redo** 는 같은 파일을 고쳐 쓰고 주석에 무엇을 왜 바꿨는지 한 줄 덧붙인 뒤 장부 `redo` 에서 뺀다.
  **skip** 은 장부 `skip` 에 `{"since": "YYYY-MM-DD", "reason": "…"}`.

## 5. 검증 — 전부 통과해야 PR

1. **실측**: `python glossary_figs.py check <이번 회차 id…>` → 문제 0(viewBox 밖·글자 겹침·상자 경계 걸침·
   상자 여백·점이나 작은 표식에 붙음/덮음 — 2 단위 안). ★영문 라벨이 국문보다 길어 **영문에서만** 붙는 일이 많다
   (09-29 첫 회차 무균조작: "particles" 끝이 막대 표식과 0.9 단위 — 사람 눈엔 'particles—'로 읽혔다). exit 2(Pretendard 미로드 = 측정 무효)면 한 번 더 돌리고, 그래도면 중단·보고.
2. **검토(눈으로 + 독립 검토자)**:
   `python glossary_figs.py sheet <이번 회차 id…> <그 용어들의 related 중 그림 있는 id…> --out <스크래치>/review.png`
   로 시트를 만들어 **직접 먼저 본다**. 그다음 Agent 도구로 검토자 **1명**(model: sonnet)에게 부록의
   검토 지시문을 그대로 주고 판정을 받는다.
   - **통과** → 채택. **수정** → 한 번 고치고 1·2를 다시. 그래도 통과가 아니면:
     새 그림은 **버리고** skip(사유 = 검토자 지적), redo 는 **원래 그림을 그대로 두고** 장부 사유에
     검토 결과를 덧붙인다 — 고치다가 더 나빠지게 하지 않는다.
   - ★검토자는 엄격한 쪽으로 기운다(09-29 보정: 기존 43장 중 25장을 걸었고, 단계 흐름을 D 로 건 것은
     과했다). 지적이 **정의 문장으로 뒷받침되지 않으면** 세션이 반박하고 채택하지 않을 수 있다 —
     반박 사유를 PR 본문에 적는다. 반대로 정의 밖 주장(A)·모순(C) 지적은 반박하지 않는다.
3. `python -m unittest web.tests.test_linkedin_cards` — 모든 그림이 두 언어로 렌더되는지, 카드 그림이 사이트
   그림과 같은지, 장부가 현실과 맞는지.
4. `python web/grm_i18n.py lint` → 0.
5. en.json 을 바꿨으면 `python web/tests/test_render.py --freeze` 후
   `git diff -U0 web/tests/golden | grep -E '^[+-]' | grep -v '^[+-][+-]' | grep -v 'i18n-en\.js?v='` 가
   **비어야 한다**(영문 골든 5장의 해시 줄만 바뀌는 게 정상). 한 줄이라도 남으면 멈추고 보고.
6. `cd web/tests && python -m unittest test_render -k Glossary` — 용어 페이지 그림 유무·영문 페이지 한글 0.
7. **전체 스위트(약 2시간)는 로컬에서 돌리지 않는다** — CI 가 본다.

## 6. PR · 머지

- `git add` 는 경로 명시(`git add -A` 금지): `web/partials/glossary_fig/<id>.html…`, `web/data/i18n/en.json`,
  `web/data/glossary_fig_review.json`, 재동결한 `web/tests/golden/en_*.expected.html`.
- 커밋 제목: `glossary(fig): YYYY-MM-DD 새 그림 N · 다시 그림 M · 보류 K — 표제어…`
- PR 본문: id 마다 **정의에서 옮긴 구조 한 줄** · 검토 판정 · (skip 이면) 사유 · (반박했으면) 반박 사유.
- `gh pr checks <n> --watch` 뒤 **`gh pr view <n> --json statusCheckRollup` 로 모든 conclusion 이 SUCCESS 인지
  명시적으로 확인**(watch 의 exit code 를 믿지 않는다) → `gh pr merge <n> --squash`.
  하나라도 실패면 머지하지 않고 원인 한 줄 보고.
- 끝나면 worktree 를 `git switch --detach origin/main`(fetch 후)으로 되돌려 다음 회차가 깨끗하게 시작하게 한다.
