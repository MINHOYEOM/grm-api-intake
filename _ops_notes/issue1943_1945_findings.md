# 2026-11-26 운영 이슈 #1943·#1945 판정

근거는 11월 25일 이슈 본문과 이 작업 트리의 코드·SQL이다. 11월 26일 운영 반영은 작업 지시에서 제공된 전제다. 운영 DB와 후속 실행 결과는 조회하지 않았다.

## #1943 · MFDS GMP 실태조사 첨부

**수집 전체 장애의 증거는 없고, 첨부 1건에 문서 단위 수동 확인이 필요하다.** 이슈에는 `pdf-ok`가 2건이고 수동 확인이 1건이다. 수집기는 같은 항목 집합에서 두 숫자를 센다. `attachment_manual_review()`는 결함표가 `unreadable`이면 PDF 본문 파싱이 성공해도 수동 확인으로 분류한다. 본문이 있고 표 행은 0개이며 지적 유무가 불명일 때 해당 상태가 가능하다. 첨부 원문이 없어 어떤 양식이나 문구가 판독을 막았는지는 확인하지 못했다.

- 안전 기준은 1건부터 경고이며 이 경고 자체는 종료 코드 0이다. 지적 유무를 확인할 수 없는 사례를 그대로 드러내고, 경고에 결함표 판독 불명과 기타 첨부 수동 확인 건수를 명시한다. 전체 PDF 파싱 집계도 함께 표시한다.
- 수집 창에 같은 문서가 남으면 다음 예약 실행에서도 집계될 수 있다. 경고 워크플로는 열린 같은 제목의 이슈를 갱신하고 코드별 경과일 사다리에서만 추가 코멘트를 남긴다. 전체 페이지에서 기존 이슈를 조회하고, 경고 배열이 유효하고 비었을 때 일치하는 열린 이슈를 모두 닫는다.
- 수동 검토 결과를 저장하는 별도 큐는 이 경보에 연결돼 있지 않다. 문서가 수집 창을 벗어나 경보가 닫혀도 해당 문서의 검토 완료를 뜻하지 않는다. 동일 첨부의 재검출 여부와 원문 판독은 후속 실측이 필요하다.

## #1945 · 번역·검수 백로그

**11월 25일에는 실제 집계 임계 초과였다.** `findings_stats()`의 두 모집단은 모두 `scope_status = 'ok'` 및 `review_status <> 'rejected'`를 조건으로 사용한다. 공개 모집단은 여기에 `finding_text_ko <> '' OR finding_language = 'KO'`가 추가된다(`web/migrations/034_findings_hide_rejected.sql`). 당시 공개 격차는 `27,845 − 27,526 = 319`로 기본 임계 300보다 19건 많았다. 검수 대기 266은 자체 임계 300 이내였다. 수집 장애나 임계가 부적절했다는 근거는 없다.

**594행 상세 재번역만으로는 초과가 해소되지 않는다.** `findings_detail_apply.py`의 상세 반영은 `detail_text`와 `detail_text_ko`만 PATCH한다. 두 필드는 공개 게이트와 검수 대기 계산에 쓰이지 않는다. 이 변경만 적용됐다는 가정에서는 격차가 319이고 검수 대기는 266이다. 별도의 `findings_translate_apply_service.py`는 `finding_text_ko`를 기록하므로, 이전에 비공개였던 대상 행이 공개 게이트를 새로 통과하면 격차를 줄일 수 있다. 다른 변화가 없으면 순감소 19행에서 300이 되어 통과하고, 18행이면 301로 여전히 초과다. 신규 유입과 별도 번역·범위·검수 상태 변화가 반영된 실제 현재 수치는 알 수 없다.

로컬 `translations/detail_outbox/`에서 작업량과 일치하는 배치를 확인했다. X-0016(133), X-0017(134), X-0023(133), X-0024(142), X-0025(15), X-FIX-0002(35), X-FIX-0003(2)의 합계가 594행이다. 해당 디렉터리를 처리하는 워크플로는 `grm-findings-detail-apply.yml`이다. 별도로 로컬 `origin/main`에 `translations/outbox/2026-11-26-483-new-obs.json`이 있어 요약 번역 경로에서도 변화가 가능하다. 운영 반영 성공·대상 행의 이전 공개 여부는 확인하지 못했다.

- 기존 워크플로는 번역·검수, 추출 격차, 국가 미매핑, 스냅샷 신선도, RPC 지연 및 읽기 오류를 모두 한 제목으로 올렸다. 번역·검수가 정상으로 돌아와도 보조 검사에 문제가 있으면 전체 실행이 실패해 #1945를 자동 종료하지 못했다.
- 임계 300은 유지하고, 번역·검수 이슈는 유효한 `findings_stats` 결과만으로 갱신·종료한다. 보조 경보와 읽기 오류는 별도 이슈를 갱신한다. 주 지표를 확인하지 못한 경우 기존 백로그 이슈를 유지하며, 전체 실행의 실패 신호도 유지한다.
- #1943·#1945의 실제 종료 여부는 확인하지 않았다. 다음 유효한 실행에서 각 조건을 다시 판단한다.
