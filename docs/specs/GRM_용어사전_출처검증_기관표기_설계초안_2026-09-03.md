# GRM 용어사전 — 출처 검증 + 기관별 표기 차이 (설계 초안)

작성 2026-09-03 · **초안. 착수 전 사용자 확인 필요.** 별도 세션에서 진행한다.

---

## 0. 이 문서를 읽는 사람에게 (불가침 전제)

**틀린 정보를 넣느니 비워 두는 것이 낫다.** 이 사전은 규제 용어를 다루고, 사용자가 실사 대응에
쓴다. 아래 규율은 협상 대상이 아니다.

1. **모든 주장에는 열어 볼 수 있는 원문이 있어야 한다.** "일반적으로 그렇다"·"업계에서는" 금지.
2. **원문을 직접 열어 확인한 것만 쓴다.** 제3자 요약·블로그·LLM 기억 금지. 2026-08-04 에
   `deviation report` 후보의 근거로 제시된 EU GMP Part I Ch.1 §1.4(xiv) 를 원문 확인하니 그 조항은
   일탈의 근본원인 분석이지 "일탈보고서" 정의가 아니어서 채택을 취소한 전례가 있다.
3. **"같다"고 단정하지 않는다.** 기관 간 용어는 완전히 같은 경우보다 **범위가 어긋나는 경우**가
   많다. 1:1 매핑으로 만들면 그 자체가 잘못된 정보가 된다(§2.3).
4. **확인하지 못하면 그 칸은 비운다.** 빈 칸은 결함이 아니라 정직한 상태다.
5. **게이트를 통과시키려 데이터를 고치지 않는다.** 위반이 나오면 사람이 무엇이 진짜 문제인지
   판단한다(`glossary_lint.py` 기존 규율과 동일).

## 1. 왜 — 지금 상태 실측 (2026-09-03, `web/data/glossary.json` 242어)

### 1.1 출처는 있는데, 그 출처의 "어디"인지가 없다

242개 **전부** `definition_source`(출처 표기 문자열)와 `source_url`(링크)을 갖고 있다. 문제는
링크가 **문서 전체**를 가리킨다는 것이다.

| 출처 문서 | 이 문서를 쓰는 용어 수 | 링크를 누르면 |
|---|---|---|
| 식약처 「알기 쉬운 GMP 용어집」 | **46** | 게시판 글 1개(§1.2) |
| EU GMP Annex 1 (2022) | **37** | 59쪽 PDF 첫 장 |
| ICH Q9(R1) | 21 | 29쪽 PDF 첫 장 |
| ICH Q7 | 17 | 49쪽 PDF 첫 장 |
| PIC/S PI 041-1 | 14 | 63쪽 PDF 첫 장 |
| WHO 용어 데이터베이스 | 13 | 검색 페이지 |
| ICH Q10 | 11 | PDF 첫 장 |
| EU GMP Annex 15 | 10 | 16쪽 PDF 첫 장 |
| MHRA GxP Data Integrity Guidance | 8 | 안내 페이지 |
| (그 외 39개 문서) | 각 1~7 | — |

고유 출처 문서는 **48개**이고 그중 29개는 용어 하나만 쓴다.

**즉 사용자가 "무균성"의 출처를 눌러도 59쪽 PDF가 열릴 뿐, 그 정의가 몇 쪽에 있는지는 알 수
없다.** 정의가 맞는지 확인하려면 PDF를 직접 뒤져야 한다. 이것이 "이 용어 정보가 사실인지도
모르잖아"의 실체다.

예외는 **21 CFR 17건**뿐이다 — `ecfr.gov/current/title-21/section-211.186` 처럼 조 단위로
직결돼 열면 바로 그 조문이 나온다. 이것이 목표 상태의 본보기다.

### 1.2 식약처 용어집은 PDF 직링크가 없다 (46건, 사전의 19%)

`https://www.mfds.go.kr/brd/m_1060/view.do?seq=12934` 는 게시판 글이고, 첨부파일은
`/common/convertDocViewer.do` 로 POST 해야 뷰어용 변환본이 나온다(2026-09-03 실측: POST 는
200 + `{"result":"success","rs":"/docviewer/result/data0011/12934/1/202609"}` 를 주지만 그 경로를
GET 하면 PDF 가 아니라 HTML 이 온다). **PDF 원본 URL 은 아직 확보하지 못했다** — 1단계에서
조사한다. 나머지 46건의 근거가 여기 걸려 있어 우선순위가 가장 높다.

또한 이 문서는 **자료실(`web/data/library/mfds.json`, 99건)에 수록돼 있지 않다**(실측: 제목에
"용어" 를 포함한 항목 0건).

### 1.3 기관별 표기 차이를 담을 자리가 없다

- `aliases` 가 **72개 용어·149건** 있지만 **전부 기관 라벨이 없다.**
- 실제로 `product-quality-review` 의 동의어에 `annual product review` 가 들어 있는데, 이것이
  "EU 계열은 PQR, 미국은 연간 품질평가" 라는 **기관 차이**라는 정보는 데이터 어디에도 없다.
  화면에는 그냥 "다른 표현"으로 나온다.
- `definition_source` 는 용어당 **한 곳**만 기록한다 — "이 개념을 FDA 는 뭐라 부르나"를 담을 수
  없는 구조다.

## 2. 무엇을 만드나

### 2.1 트랙 A — 정의의 위치까지 링크 (출처 검증)

용어마다 **"그 정의가 그 문서의 몇 쪽/몇 조에 있는가"** 를 데이터로 갖고, 화면에서 그 위치로
바로 보낸다.

```jsonc
"source_locator": {
  "kind": "pdf_page",          // pdf_page | clause_url | none
  "page": 55,                  // PDF 1-기준 물리 페이지(인쇄 쪽번호 아님 — §3.2)
  "quote_en": "Disinfection – The process by which the reduction of the number of microorganisms is achieved by the irreversible action of a product on their structure or metabolism, to a level deemed to be appropriate for a defined purpose.",
  "verified_on": "2026-09-03"
}
```

- 화면: 출처 줄이 `EU GMP Annex 1 (2022) 용어집 · 55쪽` 로 바뀌고 링크는 `…pdf#page=55`.
  원문 문장(`quote_en`)을 접이식으로 같이 보여준다 — **번역이 아니라 원문 그대로**.
- `#page=N` 은 Adobe PDF Open Parameters 규약이고 Chrome·Edge·Firefox 내장 뷰어가 지원한다.
  **다만 모든 뷰어가 지원하지는 않는다** — 지원하지 않는 환경에서는 그냥 첫 장이 열리므로
  **쪽번호를 화면 글자로도 반드시 적는다**(링크가 실패해도 사람이 찾아갈 수 있어야 한다).
- `kind: "clause_url"` 은 21 CFR 처럼 조 단위 URL 이 있는 경우(현행 17건이 이미 해당).
- `kind: "none"` 은 확인 실패 — **비워 두고 화면에도 위치를 표시하지 않는다.**

### 2.2 트랙 B — 기관별 표기 차이

```jsonc
"agency_terms": [
  {"agency": "FDA", "label": "drug product",
   "source": "21 CFR 210.3(b)(4)",
   "url": "https://www.ecfr.gov/current/title-21/section-210.3",
   "relation": "same"},
  {"agency": "EU", "label": "medicinal product",
   "source": "EudraLex Volume 4, Glossary",
   "url": "https://health.ec.europa.eu/system/files/2016-11/glos4en200408_en_0.pdf",
   "source_locator": {"kind": "pdf_page", "page": 6},
   "relation": "narrower_or_broader",
   "note": "FDA 는 완성된 제형을 가리키고, EU 정의는 '치료·예방 목적으로 제시된 물질'이라 범위가 다르다"}
]
```

- `agency` 는 **닫힌 목록**: `FDA` · `EU` · `ICH` · `PIC/S` · `WHO` · `MFDS` · `MHRA` · `HC`.
- **각 기관 표기는 그 기관 자신의 문서에서 확인한 것만** 넣는다. FDA 표기를 EU 문서에서
  확인하는 것 금지.
- `relation` 은 4값: `same`(정의가 실질적으로 일치) · `narrower_or_broader`(범위가 다름) ·
  `split`(한쪽이 둘 이상으로 나뉨) · `unverified`(대응 관계를 확정하지 못함 → 화면 미표시).

### 2.3 ★가장 중요한 함정 — 1:1 매핑이 거짓말이 되는 경우

원문 확인으로 드러난 실례:

| 개념 | FDA | EU | 관계 |
|---|---|---|---|
| 보관 검체 | **reserve sample** (21 CFR 211.170) — 원료·완제품 각각, 전 시험 필요량의 2배, 무균·발열성 제외 | **retention sample** 과 **reference sample** 이 **각각 다른 것**으로 나뉨(EU GMP Annex 19) | **`split`** — 1:1 로 이으면 틀린다 |
| 완제 의약품 | **drug product** — 21 CFR 210.3(b)(4) "완성된 제형(정제·캡슐·액제 등)으로 유효성분을 함유" | **medicinal product** — "인체·동물의 질병을 치료하거나 예방할 목적으로 제시된 물질 또는 물질의 조합" | `narrower_or_broader` |
| 제조에 투입하는 원료 | **component** — 210.3(b)(3) "의약품 제조에 사용하도록 의도된 모든 성분(완제품에 남지 않는 것 포함)" | **starting material** — "포장재를 제외한, 의약품 생산에 사용되는 모든 물질"(EudraLex Vol.4 Glossary) | `narrower_or_broader` |
| 생산 지시 원본 | **Master production and control records** — 21 CFR 211.186 | **Manufacturing Formula and Processing Instructions** — EU GMP Part I Ch.4 §§4.17–4.18 | `same`(역할 동일, 요구 항목은 다름 → note 필요) |
| 연간 품질 검토 | 21 CFR 211.180(e) — 조문에 약어 없이 "**at least annually** … quality standards of each drug product" | **Product Quality Review (PQR)** | 표기 자체가 비대칭 → note 로 설명 |

> **위 표의 인용은 2026-09-03 에 eCFR·EudraLex 원문에서 직접 확인했다.** 다만 Annex 19 의
> retention/reference sample 구분은 **아직 원문을 열어 확인하지 않았다** — 1단계에서 확인 전에는
> 데이터에 넣지 않는다.

**규칙: `relation: "same"` 은 두 정의문을 나란히 읽고 실질적으로 같을 때만 쓴다.** 확신이 없으면
`unverified` 로 두고 화면에 내보내지 않는다.

### 2.4 트랙 C — 용어집 원문을 자료실에 올린다

**현재 자료실은 링크만 저장한다** — `web/data/library/*.json` 의 항목은
`official_url`·`ko_url`·`pdf_url` 필드뿐이고, **저장소가 보유한 PDF 파일은 0개다**(실측).

그래서 "PDF 파일을 자료실처럼 둔다" 는 두 가지로 갈린다:

- **(권장) 카탈로그에 등재만 한다** — `library/` 에 "용어집" 카탈로그를 새로 만들고 각 기관
  용어집을 **원문 링크로** 올린다. 용어 카드의 출처가 이 카탈로그 항목을 참조하면 주소가 한 곳에
  모이고(자료실 주간 갱신이 링크 변경을 자동 반영), 기존 `_reg_ref_url` 이 쓰는 방식과 같다.
- **(신중) 파일 재호스팅** — 저작권·재배포 조건을 **발행기관마다 개별 확인해야 한다.** 미국
  연방규정(eCFR)은 정부 저작물이라 자유롭지만, WHO·ICH·PIC/S 는 각자 저작권 표시를 두고 있고
  재배포 조건이 문서마다 다르다. **확인 전에는 올리지 않는다.** 이 저장소는 공개 저장소라
  잘못 올리면 즉시 공개된다. (별도 이점도 없다 — §2.1 의 `#page=` 링크는 원문 링크로도 동작한다.)

## 3. 어떻게 검증하나 (이 작업의 핵심)

### 3.1 자동 대조 — "그 문장이 정말 그 문서 그 쪽에 있는가"

`quote_en` 을 저장하므로 **CI 가 기계적으로 검사할 수 있다**:

```
for 용어 in 사전:
    pdf = 그 용어의 source_url 을 받아온다
    assert quote_en 의 정규화 문자열이 pdf[page-1] 텍스트 안에 있다
```

이게 되면 "출처가 맞다"가 **주장이 아니라 재현 가능한 사실**이 된다.

**타당성 확인(2026-09-03 실측)**: 이미 받아 둔 6개 PDF(Annex 1·Annex 15·ICH Q7·Q9(R1)·
PI 041-1·EudraLex 용어집)에 대해 표제어로 페이지를 자동 특정해 본 결과 **117건 중 62건 성공**.
실패 55건의 원인은 셋이고 **셋을 구분해야 한다**:

1. **내 문서 매핑 오류** — 스파이크에서 `product-quality-review`(실제 출처 `docview/6606`,
   PE 009-17)를 `docview/4234`(PI 041-1) PDF 와 대조해 "0회 등장" 으로 나왔다. **데이터가 아니라
   내 대조 코드가 틀린 것이었다.** 자동 대조는 링크가 가리키는 **바로 그 문서**를 받아야 한다.
2. **표제어 표기 차이** — 사전은 `Active Pharmaceutical Ingredient`, ICH Q7 용어집은
   `Active Pharmaceutical Ingredient (API) (or Drug Substance)`. `Batch` ↔ `Batch (or Lot)`,
   `Quality Unit` ↔ `Quality Unit(s)`, `Expiry Date` ↔ `Expiry Date (or Expiration Date)` 도 같다.
   → 대조 기준을 표제어가 아니라 **`quote_en` 축자 문자열**로 두면 이 문제가 사라진다.
3. **그 문서에 표제 정의가 없는 경우** — 조항 서술만 있고 용어집 항목이 없는 것. 이때는
   `definition_source` 를 조항으로 바꾸거나 `kind: "none"` 으로 둔다.

**1단계는 전수 실측이다. 48개 문서를 전부 받아 242개를 대조하고, 결과를 세 갈래(확인됨 /
표기차이 / 문서에 없음)로 분류한다. 이 표가 나오기 전에는 아무것도 고치지 않는다.**

### 3.2 페이지 번호의 함정

- **물리 페이지 ≠ 인쇄 쪽번호.** 표지·목차 때문에 어긋난다(예: EU GMP Annex 1 의 인쇄 쪽번호
  "15" 는 PDF 물리 16쪽). `#page=` 는 **물리 페이지**를 받는다.
  → 데이터에는 물리 페이지를 저장하고, **화면 표기는 자동 대조로 확인된 물리 페이지 기준**임을
  밝힌다. 두 값을 섞어 쓰면 링크와 글자가 어긋난다.
- **문서가 개정되면 쪽번호가 바뀐다.** 그래서 `quote_en` 대조를 **주간 자동 검사**로 돌려야
  한다(자료실 갱신이 링크를 바꾸면 쪽번호가 조용히 틀려질 수 있다 — 기존
  `WebGlossaryRegRefLinkGuardTest` 가 막는 사고와 같은 계열).
- 원격 PDF 를 CI 가 매번 받으면 느리고 불안정하다 → **주 1회 워크플로**로 돌리고 실패는 이슈로
  표면화한다(`grm-glossary-cases.yml` 과 같은 형태).

### 3.3 새 검증 게이트 (`glossary_lint.py` 확장)

| 검사 | 위반 시 |
|---|---|
| `agency_terms[].agency` 가 닫힌 목록 밖 | ERROR |
| `agency_terms[].source`/`url` 누락 | ERROR (근거 없는 기관 표기 금지) |
| `relation` 이 4값 밖 | ERROR |
| 같은 용어 안에서 같은 `agency` 중복 | ERROR |
| `source_locator.kind == "pdf_page"` 인데 `page` 없음 / `quote_en` 없음 | ERROR |
| `quote_en` 이 해당 PDF 그 쪽에 없음 | 주간 워크플로에서 ERROR·이슈 |
| `relation: "same"` 인데 `note` 도 `quote` 도 없음 | WARNING(사람이 확인) |

기존 `WebGlossaryAliasGuardTest` 의 **도달 탐침** 방식을 그대로 쓴다 — 필드 존재가 아니라
"그 표현으로 검색하면 그 용어가 나오는가"를 검사한다. 기관 표기는 검색에도 들어가야 한다
(`medicinal product 뜻` 으로 지금은 아무것도 안 나온다).

## 4. 범위와 순서

242어 × 8기관 = 1,936칸을 채우는 것은 **비현실적이고 필요하지도 않다.** 실제로 표기가 갈리는
것만 다룬다.

| 단계 | 내용 | 산출물 |
|---|---|---|

## 5. 건드리지 말 것 (기존 계약)

- `related` 의 **순서는 정본**이다(사람 큐레이션). 코드가 재정렬하지 않는다.
- `glossary_cases.json` 의 `q`(검색어)와 `excluded` 49건은 사람이 판정한 값 — 자동 갱신 대상이
  아니다. 사례를 지어내 채우지 않는다.
- `aliases` 는 **검색용 전량 / 표시용은 표제어와 같아지는 것을 감춘다**. 기관 표기를 추가할 때
  이 규율을 깨지 않는다(표제어가 동의어를 이긴다).
- `detail_ko`("실무 맥락")는 2026-09-03 에 템플릿 복제 109건을 삭제해 133건만 남았다.
  **다시 채우려면 그 용어만의 실사 맥락을 조항 근거와 함께** 쓴다 — 템플릿 복제는
  `glossary_lint.py` 가 신규 id 로 잡아 ERROR 를 낸다(기준선은 빈 집합이며 늘리지 않는다).
- `GRM_SYSTEM.md` 갱신 필요(어휘 수·새 필드·새 워크플로) — 다른 세션이 이 파일을 잡고 있는지
  먼저 확인한다.
