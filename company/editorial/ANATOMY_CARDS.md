# 링크드인 '사건 해부형' 카드 — 설계 (2026-11-03 시범)

벤치마크(HoJin Lee) 카드 6장 구성을 우리 결과물로 옮기는 설계다. 구현은 `web/linkedin_anatomy.py`(시범, 별도 CLI),
문체는 `STYLE.md`, 시범 결과는 `STYLE_PILOT_2026-11-02.md`.

## 한눈에

| 장 | 벤치마크 | 우리 구현(`kind`) | 문장의 출처 |
|---|---|---|---|
| 01 | 판단이 든 헤드라인 + 서한에 적힌 수치 막대 3개 | `a_cover` | 헤드라인·막대 라벨 = **슬롯**, 막대 값 = **근거 문장 안의 숫자**(코드가 검증) |
| 02 | FDA 지적 내용 표 (무엇이·어떻게·결과·다른 신호) | `a_table` | 슬롯 4행, 행마다 `evidence`(서한 문장 verbatim) 필수 |
| 03 | 근본원인 3단 흐름 + FDA 관점 vs 점검 제안 | `a_flow` | `fda_quote` = 서한 문장 verbatim(코드 검증) · `proposal`·`not_stated` 은 칸을 갈라 표시 |
| 04 | 시정조치 FDA 요구사항 번호 박스 | `a_boxes` | 박스 수 = 서한의 요구 항목 수(코드 검증: 하나도 빼면 거부) · 회신 기한 = **코드**가 `required_remediation.deadline`에서 추출 |
| 05 | 예방조치와 유효성 확인 | `a_pairs` | 회사 회신 → FDA 판단 대비(`fda_evaluation` 근거 verbatim) + 반복 위반 + "서한은 유효성 기준을 기재하지 않는다 / 점검 제안" |
| 06 | 시사점: 체크리스트 3 + 질문 1 | `a_check` | 슬롯. 전부 `?` 로 끝나야 통과(명사 나열 거부) |

본문(캡션)은 첫 문장(조항) → 사실 → 회신 대비 → 요구 → 질문 → 해시태그, 영문 본문 병기. 같은 슬롯에서 조립한다.

## 비용 0 구조 — 코드가 쥐고, LLM 은 슬롯만, 코드가 다시 검증

```
브리프 JSON(발행본)  ──코드──▶ 대상 카드 선정 + 사실 필드(발행일·기한·요구 수·원문 문장)
                                   │
        구독 경로 LLM(클라우드 Routine / 로컬 세션)이 STYLE.md 로 슬롯 JSON 작성
        web/data/linkedin_anatomy/<발행일>.json        ← 유료 API 호출 코드 없음
                                   │
              validate_slots(): 근거 verbatim · 숫자 · AI 티 · 실명 · 요구 누락 · 질문형 · 글자 수
                                   │ 통과                         │ 하나라도 실패
                               6장 PNG + 본문                종전 8장 덱 그대로(발행 안 함·사유 출력)
```

- `evidence` 는 카드의 **원문 부분 문자열**이어야 한다(`description` 국문 번역 또는 `original` 영문). 숫자는 근거 안에 있어야 한다.
- 슬롯 작성자가 환각을 써도 숫자·근거 인용이면 막힌다. 패러프레이즈가 원문 뜻을 바꾸는 것은 못 막는다 → 교열(사람/세션)이 원문 대조.
- 서한에 없는 말은 `not_stated`("서한은 ○○를 기재하지 않는다 — 점검 항목은 제안")와 `proposal`로 나눈다. 카드의 노란 상자에 나온다.

## 대상 선정 — 제안(대표 결정 사항)

**제안: 주당 경고서한 1건, 규칙으로 고른 "구체 수치가 가장 많은 1건". 후보 3건까지 `--candidates` 로 보여 주고 사람이 바꿀 수 있다.**

근거(최근 14호 실측, `web/data/briefs/`):
- 경고서한이 있는 주는 13/14호(08-03 호만 0건). 주당 1~7건, 중앙값 약 3건. 본문이 확보된(`source_body_captured`) 서한 중 FDA 평가와 요구가 있는 것이 거의 전부(08-17 호만 본문 미확보 2건) — 해부는 **거의 매주 가능**하다.
- "가장 영향 큰 1건"은 주관이라 AI 가 고르면 근거를 설명할 수 없다. 규칙: ① 신호 등급(`signal_tier`) → ② 서한에 적힌 구체 수치 수(해부 카드 막대·표가 숫자에서 나오므로 숫자가 많은 서한이 좋은 카드가 된다) → ③ 지적 건수 → ④ 앞선 순서. 11-02 호 결과: Northland(11) > TSP(1) = Sanrace(1) — 숫자 밀도 차이가 크다.
- 한 주에 서한이 7건이어도 6장 한 편이다. 나머지는 종전 8장 덱·사이트 브리프가 맡는다(10-05 호처럼 서한이 몰린 주를 포함해도 하루 한 편 해부는 HoJin 의 연재 속도와 같다).
- 해부가 불가능한 주(서한 0건, 본문 미확보)는 **종전 8장 덱을 그대로** 낸다. 억지 사건을 만들지 않는다.
- 대안: 가장 많이 읽힌 사건(RUM)·가장 많이 검색된 사건을 고르는 방식은 발행 시점(월요일)에 데이터가 없어 채택하지 않았다. 483·회수도 같은 틀로 해부할 수 있으나 서한처럼 '회신 → 판단' 대비가 없어 6장 구성이 맞지 않는다(별도 설계).

## 현행 출력 보호 · 전환 절차

- 이 PR 은 `linkedin_cards.main`·`build_deck` 출력을 **바꾸지 않는다**(02 카드 '업체' 버그 수정 제외). 해부형은 `python web/linkedin_anatomy.py --brief … --slots … --out …` 로만 나온다. 슬롯이 없으면 아무것도 만들지 않는다.
- 전환(대표 승인 후, 별도 PR): ① `linkedin_cards.py` 에 `--deck anatomy|weekly`(기본 weekly) ② 월요일 링크드인 Routine 프롬프트가 슬롯을 쓰고 `validate_slots` 통과 확인 ③ 영문판 결정(아래) ④ `GRM_SYSTEM.md` 보조 채널 문단.
- `en.json` 은 건드리지 않았다(새 문구는 PNG·본문 문자열이고 사이트 템플릿 문구가 아니다). 영문 골든 재동결 불필요.

## 열린 결정(대표)
1. 익명 정책: 링크드인 카드는 익명(시범)으로 했다 — 사이트는 실명 유지. 맞는지.
2. 이미지 하단 'AI 도구로 생성' 고지: 시범은 종전 위치(전 장 최하단) 유지. 위치·표현 변경은 정책 결정.
3. 영문 본문은 국문 뒤 병기(시범). 영문 카드 6장은 만들지 않았다(PNG 는 국문만).
4. 용어 풀이: 카드 안 풀이는 슬롯이 쓴다. 용어사전 `easy_ko` 와 같은 뜻이라는 보장은 아직 사람이 본다(자동 대조는 후속).
