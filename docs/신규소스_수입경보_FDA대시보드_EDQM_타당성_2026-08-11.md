## 2. FDA 수입경보 (Import Alert 66-40 · 66-41) 〔채택 — 조건부〕

### 2.1 무엇
제조소 단위 **무검사 자동억류(DWPE, Detention Without Physical Examination)** 목록. GRM이 가진 다른 모든 소스가 "과거에 일어난 사건"인 데 반해, 수입경보는 **오늘 현재의 상태**("이 제조소는 지금 미국 수입이 막혀 있다")를 말하는 유일한 채널이다.

### 2.2 접근성·구조 (2026-08-11 실측)
- `https://www.accessdata.fda.gov/cms_ia/importalert_189.html` = IA **66-40** (1.9 MB, HTTP 200)
- `https://www.accessdata.fda.gov/cms_ia/importalert_190.html` = IA **66-41** (6.7 MB, HTTP 200)
- 한국 IP에서 정상 수신. `www.fda.gov` 최상위 도메인과 달리 Akamai 봇차단에 걸리지 않았다.
- **`<table>` 0개.** 업체 1건 = `<div class="div-info">` 블록 하나:
  - `<div class="div-name floatleft">` 회사명
  - `<div class="div-name floatright">Date Published : MM/DD/YYYY</div>`
  - `<div class="clear">` 주소, 도시, 국가
  - 이어서 제품코드마다 별도 `<div>`(클래스 없음) + 자체 `Date Published:`
- 두 알림 모두 **Red List만 존재**(Green/Yellow List 앵커·문자열 0건).

### 2.3 볼륨·한국 관련성
| | 업체 수 | 한국 등재 |
|---|---:|---:|
| IA 66-40 | 465 | 37 |
| IA 66-41 | 1,920 | 94 |
| 합계(정규화 중복제거) | 2,163 | 115 |

- 66-40 상위국: 중국 156 · 인도 108 · **한국 37** · 캐나다 27 · 멕시코 17
- 66-41 상위국: 인도 286 · 캐나다 242 · 중국 234 · 멕시코 99 · **한국 94**
- 등재된 국내 업체에 **대형사가 다수 포함**된다(COSMAX, COSRX, LG H&H, 아모레퍼시픽 데일리뷰티 플랜트, 한국콜마, 휴젤, 메디톡스, 휴온스, 녹십자 음성공장 등). 사내 사용자에게 즉각적 관련성이 있다.

### 2.4 채택 근거 — 두 가지 결정적 실측
착수 전 반드시 확인해야 했던 두 질문에 대한 답이 모두 긍정이었다.

**(1) 날짜 필드가 있는가 → 있다.**
`Date Published (MM/DD/YYYY)`가 업체 레벨 **100%**(465/465, 1920/1920), 제품코드 레벨에도 개별 존재. 그중 66-40은 62.4%, 66-41은 27.8%가 **업체 헤더 날짜와 다른 값**이다 — 즉 이 날짜는 형식적 텍스트가 아니라 실제 추가 시점을 반영한다. **"이번 주 신규 등재"를 만들 수 있다.** 이 필드가 없었다면 주간 브리프에 실을 수 없어 채택 근거가 무너졌을 것이다.

**(2) 이미 아는 정보인가 → 아니다.**
findings의 `firm_name`(distinct 3,166)과 정규화 대조한 중복도는 **전체 7.3% · 한국만 14.8%**. 즉 들여올 정보의 **85~93%가 현재 DB에 없는 업체**다. `finding_text`의 `import alert` 언급도 16,986건 중 17건(0.1%)뿐이고, 그 17건조차 DEG/EG 오염 관련 별개 경보를 가리킨다 — 지금 483/경고서한 경로로 대체 커버되고 있다는 증거는 없다.

### 2.5 반대 근거(무시하지 말 것)
- **정보 깊이가 얕다.** 업체명·주소·제품코드·날짜뿐이고 위반사유 서술이 없다 → `finding_text`를 채울 실질 내용이 없다. **기존 findings 스키마에 그대로 끼워 넣으면 스키마 목적과 어긋난다.**
- **해제일 필드가 없다.** '해제됨'은 스냅샷 diff로만 추정 가능하고, 수집을 한 번이라도 건너뛰면 그 사이 해제/재등재 이력이 영영 유실된다. (일일 크론이 실제로 며칠 침묵한 전례가 있다.)
- **파서가 취약하다.** 필드 구분이 `div-name floatleft/floatright` 같은 **프레젠테이션 클래스뿐**이고 의미론적 마크업(`itemprop`, `data-*`)이 전혀 없다. FDA CMS 리디자인 시 조용히 깨진다.
- **문서 내부 표기 불일치.** 66-40에 13건, 66-41에 65건의 중복명(같은 업체·다른 대소문자/구두점/법인격 접미어). **정규화 없이 문자열 diff를 돌리면 같은 업체가 매주 '신규'로 오탐된다.**
- **갱신 주기 미검증.** HTTP `Last-Modified: 2026-08-07` 단일 스냅샷만 봤다. 실제 갱신 주기는 1~2주 뒤 재수집 diff로 확인해야 한다.

### 2.6 착수 지시 (요약)
1. **findings 테이블에 넣지 마라.** 별도 경량 리스트형 테이블(업체·주소·국가·제품코드·등재일·알림번호)을 신설한다. 서술형 스키마와 목적이 다르다.
2. 2.5의 정규화 로직(대문자화 → 영숫자 외 공백 치환 → 법인격 접미어 토큰 제거 → 연결)을 **파이프라인에 필수로 내장**한다. 문서 내부 중복부터 정리되지 않으면 신규 탐지가 성립하지 않는다.
3. **스냅샷 원본을 보관**한다. 해제일이 없으므로 스냅샷이 유일한 이력이다.
4. 발행(브리프 카드·페이지)은 **최소 2주 재수집 diff로 갱신 주기를 확인한 뒤** 연다. 수집·보관을 먼저 시작해야 그 검증이 가능하다.
5. 범위는 이 두 알림에 한정한다. FDA 수입경보는 90개 이상이고 전량 확장 시 물량이 findings(16,986)를 압도한다.

## 3. FDA Data Dashboard (실사 등급·조항 인용 통계) 〔보류 — 키 신청 선행〕

### 3.1 무엇·왜 원했나
GRM은 현재 **분자만** 갖고 있다("지적 11,489건"). 실사 자체의 모수(실사 건수, 등급 NAI/VAI/OAI, 조항별 인용 통계)가 없어 "많은지 적은지"를 말할 기준이 없다. 이걸 붙이면 "실사 M건 중 N건", "업종별 OAI 비율"을 말할 수 있게 된다.

### 3.2 판정: **무인증 경로는 존재하지 않는다** (4개 후보 전수 실측)
| 후보 | 결과 |
|---|---|
| 정적 다운로드 파일(`datadashboard.fda.gov/InspectionsDataset.xlsx` 등) | **404**(진짜 IIS 오류, 봇차단 아님). HTML의 `href`는 죽은 폴백이고 실제 동작은 `onclick="exportData(...)"`가 가로챈다 — Qlik Sense JS 엔진의 **살아있는 WebSocket 세션**이 있어야만 내려받아진다. curl로는 원천적으로 불가 |
| 배후 REST API `api-datadashboard.fda.gov/v1/*` | 엔드포인트 실재. 필드 검증까지 통과시킨 유효 요청에도 **401 Not Authorized** 확정. `Authorization-User`/`Authorization-Key` 필수 |
| openFDA (`api.fda.gov`) | `download.json` 카탈로그 전수 확인 — 실사·인용·수입거부 엔드포인트가 **애초에 없다** |
| 레거시 `accessdata.fda.gov/scripts/inspsearch/` | **404**(폐기) |

### 3.3 사람이 해야 할 일 (사용자 액션)
**OII Unified Logon**으로 Data Dashboard API 키를 신청한다. 필요 정보는 이메일·이름·성·소속기관이며, openFDA처럼 즉시 자율발급이 아니라 **승인 대기형**이다. 안내 페이지: `https://datadashboard.fda.gov/oii/api/index.htm`

> ⚠️ **openFDA 키와 별개 시스템이다.** 이미 `OPENFDA_API_KEY`를 갖고 있어도 이 API에는 통하지 않는다.

### 3.4 주의
`www.fda.gov` 최상위 도메인은 Akamai 봇탐지로 비브라우저 UA를 차단한다(실측: 404 → `abuse-detection-apology.html`로 리다이렉트). 이 트랙을 자동화에 넣을 때 fda.gov 페이지 스크래핑 단계마다 걸린다.

## 4. EDQM CEP Actions 〔채택 — 2026-06-11 권고가 미착수 상태였음〕

### 4.1 미착수 사실
`신규소스_EudraGMDP_EDQM_타당성_2026-06-11.md` §3에서 **"채택 권고, 2순위, 난이도 낮음"**으로 판정됐고 §4에서 도입 순서 2번으로 지정됐다. 1순위였던 EudraGMDP NCR은 구현·라이브됐으나(소스 14), **EDQM CEP는 두 달이 지나도록 코드가 존재하지 않는다**(`collect_edqm_cep.py` 부재, 저장소 전수 grep 결과 EDQM 참조 0건).

### 4.2 무엇 — 왜 다른 소스와 겹치지 않는가
유럽약전 적합성인증(CEP)의 **정지·철회·복원** 공개 목록. CEP는 **원료(API)**가 약전 모노그래프에 적합함을 인증하는 것이라, 정지/철회는 곧 **원료 공급 적합성 리스크**다.

GRM의 기존 7개 레인은 전부 **제조소(사이트) 관점**이다. EDQM만 **원료·물질 관점**이라 구조적으로 겹치지 않는다. EudraGMDP NCR과는 상보 관계이고, EDQM 페이지 자체가 "Read the current Non-Compliance Reports" 링크로 EudraGMDP를 가리켜 두 소스의 연계가 원문에서 확인된다.

국내 제약사에 직접적이다 — 원료를 어디서 받는지가 곧 리스크이기 때문이다.

### 4.3 접근성 — 착수 전 최대 미지였고, 이번에 해결했다 (2026-08-11 실측)
`https://www.edqm.eu/en/actions-on-ceps`

| 요청 방식 | 결과 |
|---|---|
| 기본 UA (curl 기본값) | **403 × 5/5** (5.4 KB 차단 페이지) |
| 브라우저 UA | **200 × 5/5** (226 KB 정상 본문) |
| 브라우저 UA + Accept 헤더 (연속 11회째부터) | 200 × 3 / 403 × 2 — 연타 시 레이트리밋 |

**판정: `UA_GATED`.** 브라우저 UA만 주면 안정적으로 열린다. 이 저장소는 FDA 483·MFDS에서 이미 브라우저 UA 방식을 쓰고 있어 새로 만들 것이 없다. 레이트리밋은 **단일 페이지·1일 1회 수집**이라 실무상 무관하다.

구조 실측(226 KB 본문): `<table>` 7개 / `<tr>` 29행, `Suspension`·`Withdrawal`·`Restoration` 각 4회, `non-compliance` 9회 — 2026-06-11 조사가 기술한 섹션 구조가 **오늘도 유효**하다.

### 4.4 착수 지시 (요약)
- 2026-06-11 문서 §3.3의 매핑을 그대로 쓴다: `document_id` = CEP 번호 + 액션유형 + 사유 + 날짜, `firm_or_product` = Substance name, Region = EU/EDQM.
- 파서는 **섹션 헤더 앵커 기반**으로 짠다(사람이 큐레이팅한 HTML이라 레이아웃 변경에 취약).
- 날짜 포맷 혼재를 방어 파싱한다(선행 조사가 `22/09//2023` 같은 오타를 실측했다).
- 저빈도 소스이므로 **일일 0건이 정상**이다 — 최소건수 게이트를 걸면 "소스가 죽었다"는 오진을 부른다.
- `ENABLE_EDQM_CEP`(기본 off) + dry-run 라이브 검증 후 운영 ON. 기존 opt-in 소스 관례 그대로.

## 5. 왜 이번 세션에서 구현하지 않았는가

셋 다 **동시 편집 충돌**이 확실하기 때문이다. 이 시점에 별도 세션이 Health Canada 실사 수집기와 WHOPIR PDF 파싱을 진행 중이고, 새 intake 소스를 추가하려면 양쪽이 똑같이 `collect_intake.py`·`card_scaffold.py`·`findings_extractors.py`·`.github/workflows/grm-intake.yml`을 건드려야 한다. 이 저장소는 병렬 세션이 같은 파일을 만져 사고가 난 전례가 있다.

수입경보는 추가로 **갱신 주기가 미검증**이고, FDA Data Dashboard는 **사람의 키 신청이 물리적 선행조건**이다.

세 건 모두 착수 전 최대 미지(접근성·날짜 필드·중복도·무인증 가능성)를 이 문서가 실측으로 해소했으므로, 다음 세션은 조사 없이 바로 구현에 들어갈 수 있다.
